§ 1

Games as Adversarial Search Problems

In a multi-agent competitive environment, the actions of other agents directly oppose our goals. In AI, these are formalized as adversarial search problems, commonly referred to as games.

6 SIX COMPONENTS OF A FORMAL GAME DEFINITION
  1. Initial State ($s_0$): The board configuration and specification of which player moves first.
  2. $Player(s)$ Returns: The player whose turn it is to move in state $s$ (e.g. $MAX$ or $MIN$).
  3. $Actions(s)$ Returns: The set of legal moves permissible in state $s$.
  4. Transition Model $Result(s, a)$: Returns the state resulting from taking action $a$ in state $s$.
  5. Terminal Test $TerminalTest(s)$: True if the game has ended (win, loss, or draw); False otherwise. States where the game has ended are called terminal states.
  6. Utility Function $Utility(s, p)$: (Also called objective function or payoff function). Assigns a numerical value to terminal state $s$ for player $p$. In chess: $+1$ for win, $0$ for draw, $-1$ for loss.

Zero-Sum Games: Games where the sum of payoffs to all players is constant (usually zero). A gain for MAX is an exact, equal loss for MIN: $Utility_{MAX}(s) = -Utility_{MIN}(s)$.

QUICK RECALL
  • 6 Components: Initial state, Player(s), Actions(s), Result(s, a), TerminalTest(s), Utility(s, p).
  • Zero-sum: what is good for MAX is equally bad for MIN ($U_{MAX} = -U_{MIN}$).
  • Deterministic, fully observable, zero-sum games: Chess, Checkers, Go, Tic-Tac-Toe.
§ 2

The Minimax Algorithm

The Minimax algorithm computes the optimal move for player MAX under the assumption that the adversary MIN plays perfectly (optimally) to minimize MAX's outcome.

RECURSIVE MINIMAX VALUE DEFINITION $$\mathbf{\text{Minimax}(s) = \begin{cases} \text{Utility}(s) & \text{if } TerminalTest(s) \\ \max_{a \in Actions(s)} \text{Minimax}(Result(s, a)) & \text{if } Player(s) = MAX \\ \min_{a \in Actions(s)} \text{Minimax}(Result(s, a)) & \text{if } Player(s) = MIN \end{cases}}$$

Properties of the Minimax Algorithm

  • Completeness: Yes, if the game tree is finite.
  • Optimality: Yes, against an optimal adversary. (If the opponent plays suboptimally, Minimax still guarantees at least the minimax value or better).
  • Time Complexity: $O(b^m)$, where $b$ is the legal branching factor and $m$ is the maximum depth of the game tree. Performs a full depth-first exploration.
  • Space Complexity: $O(bm)$ — linear space for depth-first recursion.
THE INTRACTABILITY OF PURE MINIMAX

For Chess ($b \approx 35, m \approx 80$), Minimax would evaluate $35^{80} \approx 10^{123}$ terminal nodes! In comparison, the observable universe contains only $\sim 10^{80}$ atoms. Pure Minimax cannot be computed completely; practical game programs use Alpha-Beta Pruning combined with heuristic evaluation functions and depth cutoffs.

QUICK RECALL
  • MAX chooses action maximizing child values ($\max$).
  • MIN chooses action minimizing child values ($\min$).
  • Time: $O(b^m)$ (exponential); Space: $O(bm)$ (linear).
§ 3

Alpha-Beta Pruning

Alpha-Beta pruning is a pruning technique that returns the exact same mathematical decision as Minimax, but systematically eliminates subtrees that cannot possibly influence the final decision.

THE TWO BOUNDING PARAMETERS
  • $\alpha$ (Alpha): The value of the best (highest-value) choice found so far along the path for MAX. Initialized to $-\infty$.
  • $\beta$ (Beta): The value of the best (lowest-value) choice found so far along the path for MIN. Initialized to $+\infty$.
ALPHA-BETA PRUNING CUTOFF RULE

As search proceeds down the tree, the $[\alpha, \beta]$ window shrinks. Whenever:

$$\mathbf{\beta \le \alpha}$$

the remaining children of the current node are pruned immediately (alpha cutoff at a MIN node, or beta cutoff at a MAX node).

Reason: MAX already has an option of value $\alpha$ elsewhere, while MIN has an option of value $\le \beta$ here. Since $\beta \le \alpha$, MAX will never allow the game to enter this branch!

Alpha-Beta Pruning Step-by-Step Game Tree Trace

Consider a 2-ply game tree with root $\mathbf{Root}$ (MAX). Root has three children $B, C, D$ (MIN nodes):

  • Node B has leaf children with terminal values: $[3, 12, 8]$
  • Node C has leaf children with terminal values: $[2, 4, 6]$
  • Node D has leaf children with terminal values: $[14, 5, 2]$

Execute Alpha-Beta pruning from left to right. Identify the root value and all pruned subtrees.

Step 1: Evaluate Subtree at Node B (MIN):

  • At Root: $\alpha = -\infty, \beta = +\infty$. Calls $B$ with $\alpha = -\infty, \beta = +\infty$.
  • $B$ evaluates first leaf $3$: $\beta = \min(+\infty, 3) = \mathbf{3}$.
  • $B$ evaluates second leaf $12$: $\beta = \min(3, 12) = 3$.
  • $B$ evaluates third leaf $8$: $\beta = \min(3, 8) = 3$.
  • $B$ returns value $3$.
  • Back at Root (MAX): updates $\alpha = \max(-\infty, 3) = \mathbf{3}$. Window at Root: $[\alpha = 3, \beta = +\infty]$.

Step 2: Evaluate Subtree at Node C (MIN):

  • Root calls $C$ passing current window: $\alpha = 3, \beta = +\infty$.
  • $C$ evaluates first leaf $2$: $\beta = \min(+\infty, 2) = \mathbf{2}$.
  • Test Pruning Condition at Node C: $$\beta \le \alpha \implies 2 \le 3 \quad \mathbf{\text{[TRUE: PRUNE!]}}$$
  • Since $2 \le 3$, MIN can already force a score of at most 2 here. But MAX already has a guaranteed 3 from branch $B$. MAX will never pick $C$.
  • → PRUNE leaves 4 and 6 of Node C! (Never evaluated). Node $C$ returns $\le 2$.

Step 3: Evaluate Subtree at Node D (MIN):

  • Root calls $D$ passing $\alpha = 3, \beta = +\infty$.
  • $D$ evaluates first leaf $14$: $\beta = \min(+\infty, 14) = 14$. ($\beta > \alpha$).
  • $D$ evaluates second leaf $5$: $\beta = \min(14, 5) = 5$. ($\beta > \alpha$).
  • $D$ evaluates third leaf $2$: $\beta = \min(5, 2) = \mathbf{2}$.
  • Now $\beta \le \alpha$ ($2 \le 3$). Since all children of $D$ were already evaluated, $D$ simply returns $2$.

Step 4: Final Decision at Root (MAX):

$$\text{Root} = \max(B=3, C \le 2, D=2) = \mathbf{3}$$

Results:

  • Optimal Move for MAX: Branch B with Minimax Value $= \mathbf{3}$.
  • Pruned Branches: Leaves 4 and 6 under Node C were successfully pruned!

Effectiveness of Alpha-Beta Pruning

The number of pruned nodes depends heavily on move ordering (evaluating the best moves first):

Move Ordering Time Complexity Pruning Efficiency
Worst Case (Worst moves evaluated first) $$O(b^m)$$ No pruning occurs. Evaluates all minimax nodes.
Random Move Ordering $$O(b^{3m/4})$$ Substantial pruning.
Best Case (Perfect move ordering: best moves first) $$O(b^{m/2}) = O((\sqrt{b})^m)$$ Doubles the search horizon! Can search twice as deep in the same amount of time.
QUICK RECALL
  • $\alpha$: best value for MAX so far ($-\infty$). $\beta$: best value for MIN so far ($+\infty$).
  • Prune whenever $\beta \le \alpha$.
  • With perfect move ordering, alpha-beta reduces complexity to $O(b^{m/2})$, doubling searchable depth!
§ 4

Constraint Satisfaction Problems (CSP)

Standard search treats states as atomic "black boxes" with no internal structure. In a Constraint Satisfaction Problem (CSP), states are factored into a set of variables, each taking a value from a domain, and the goal is to find an assignment that satisfies a set of explicit constraints.

FORMAL DEFINITION OF A CSP

A CSP is formally specified as a triplet:

$$\mathbf{\{X, D, C\}}$$
  • $\mathbf{X = \{X_1, X_2, \dots, X_n\}}$: A finite set of variables.
  • $\mathbf{D = \{D_1, D_2, \dots, D_n\}}$: A set of domains, where $D_i$ is the set of allowable values for variable $X_i$.
  • $\mathbf{C = \{C_1, C_2, \dots, C_m\}}$: A set of constraints. Each constraint $C_i = \langle scope, rel \rangle$ consists of a tuple of variables that participate in the constraint and a relation defining allowable value combinations.

Constraint Taxonomy

  • Unary Constraint: Restricts the value of a single variable (e.g. $SA \ne \text{Green}$).
  • Binary Constraint: Relates two variables (e.g. $SA \ne WA$). Binary CSPs can be visualized as a Constraint Graph where variables are nodes and constraints are edges.
  • Higher-Order / Global Constraints: Involve 3 or more variables. Classic example: $\text{Alldiff}(X_1, X_2, \dots, X_k)$, which mandates that all participating variables take distinct values (e.g. Sudoku).
QUICK RECALL
  • CSP = $\{X, D, C\}$ (Variables, Domains, Constraints).
  • Constraint graph: Nodes = variables; Edges = binary constraints.
  • Consistent assignment: violates no constraints. Complete assignment: every variable is assigned.
§ 5

Constraint Propagation & The AC-3 Arc Consistency Algorithm

Rather than searching blindly, a CSP agent can interleave search with constraint propagation: using constraints to eliminate impossible values from variable domains before making choices.

DEFINITION: ARC CONSISTENCY

A directed arc $(X_i, X_j)$ in the constraint graph is arc-consistent if and only if for every value $x \in D_i$, there exists at least one value $y \in D_j$ such that the pair $(x, y)$ satisfies the constraint between $X_i$ and $X_j$.

THE AC-3 ALGORITHM (STEP-BY-STEP)
  1. Initialize a queue $Q$ with all directed binary arcs in the CSP: $Q = \{(X_i, X_j) \mid \text{binary constraint exists between } X_i, X_j\}$. (Each undirected constraint corresponds to two directed arcs $(X_i, X_j)$ and $(X_j, X_i)$).
  2. While $Q$ is not empty:
    • Remove arc $(X_i, X_j)$ from $Q$.
    • Call Revise(CSP, Xi, Xj): For each $x \in D_i$, if no value $y \in D_j$ satisfies the constraint with $x$, remove $x$ from $D_i$.
    • If Revise removed any value from $D_i$:
      • If $D_i = \emptyset$, return False (inconsistent CSP, no solution!).
      • For every neighbor $X_k$ of $X_i$ (where $X_k \ne X_j$), re-insert the arc $(X_k, X_i)$ into $Q$ because shrinking $D_i$ may cause $X_k$ to become inconsistent!
  3. Return True (all domains are now arc-consistent).

AC-3 Arc Consistency on Australia Map Coloring

Variables: $\{WA, NT, SA, Q, NSW, V, T\}$. Domains: $\{Red, Green, Blue\}$. Constraint: Adjacent regions cannot share the same color. Suppose the search assigns $\mathbf{WA = \{Red\}}$. Trace AC-3 propagation.

Step 1: Check Arc $(NT, WA)$:

$WA = \{Red\}$. For $x = Red \in D_{NT}$, no value in $D_{WA}$ satisfies $Red \ne Red$. → Remove $Red$ from $D_{NT}$! $D_{NT} = \{Green, Blue\}$.

Step 2: Check Arc $(SA, WA)$:

For $x = Red \in D_{SA}$, conflict with $WA$. → Remove $Red$ from $D_{SA}$! $D_{SA} = \{Green, Blue\}$.

Step 3: Check Arc $(NT, SA)$:

For each value in $D_{NT} = \{Green, Blue\}$, there is an alternate color in $D_{SA} = \{Green, Blue\}$ (if $NT=Green$, $SA=Blue$). → Arc is consistent without removals.

Reduced Domains after AC-3:

  • $WA = \{Red\}$
  • $NT = \{Green, Blue\}$ (Red pruned!)
  • $SA = \{Green, Blue\}$ (Red pruned!)
  • $Q, NSW, V, T = \{Red, Green, Blue\}$ (Unaffected mainland & isolated Tasmania)
QUICK RECALL
  • Arc $(X_i, X_j)$ is consistent if every $x \in D_i$ has a valid partner in $D_j$.
  • If `Revise` deletes a value from $D_i$, re-enqueue all arcs $(X_k, X_i)$ entering $X_i$.
  • AC-3 time complexity: $O(c d^3)$, where $c$ is constraints and $d$ is domain size.
§ 6

Backtracking Search & Intelligent Heuristics

Backtracking search is the fundamental uninformed algorithm for solving CSPs. It performs depth-first search, assigning one variable at a time, and backtracks immediately when a variable has no legal values.

Three Intelligent Heuristics for CSP Search

Heuristic Name Selection Target Operational Rule & Intuition
1. Minimum Remaining Values (MRV)
(Most Constrained Variable / "Fail-First")		 Variable Selection Choose the unassigned variable with the fewest remaining legal values in its domain.
Intuition: Minimizes branching factor and detects inevitable failure as early as possible.
2. Degree Heuristic
(Tie-breaker for MRV)		 Variable Selection Choose the unassigned variable with the largest number of constraints on other unassigned variables.
Intuition: Imposes the greatest reduction on neighboring domains early in the search tree.
3. Least Constraining Value (LCV)
("Fail-Last")		 Value Selection Given a selected variable, choose the value that rules out the fewest choices for neighboring variables.
Intuition: Leaves maximum flexibility for subsequent variable assignments.
MNEMONIC: VARIABLE VS VALUE SELECTION

For choosing which variable to assign: be pessimistic → Fail-First (MRV, Degree Heuristic).

For choosing which value to assign: be optimistic → Fail-Last (Least Constraining Value).

QUICK RECALL
  • MRV (variable): pick variable with fewest legal values left.
  • Degree Heuristic (variable): tie-breaker; pick variable with most constraints on other unassigned variables.
  • LCV (value): pick value ruling out fewest choices for neighbors.
§ 7

Forward Checking & Maintaining Arc Consistency (MAC)

Instead of waiting for a contradiction, a search algorithm can detect dead-ends proactively by propagating constraints during the search process.

Forward Checking

Whenever a variable $X$ is assigned a value $x$, Forward Checking looks ahead at each unassigned neighbor $Y$ connected to $X$ by a constraint, and deletes from $D_Y$ any value that is inconsistent with $x$. If any domain becomes completely empty ($D_Y = \emptyset$), the algorithm backtracks immediately!

LIMITATION OF FORWARD CHECKING

Forward checking only looks at constraints between the current variable and its neighbors. It does NOT detect inconsistencies between two unassigned neighbors! For example, if two unassigned neighbors both have domain $\{Green\}$, forward checking will not detect that they must conflict until one of them is assigned.

Maintaining Arc Consistency (MAC)

MAC is a more powerful algorithm: after a variable $X_i$ is assigned, it runs a full AC-3 algorithm initialized with arcs $(X_j, X_i)$ for all unassigned neighbors $X_j$. MAC detects deep multi-variable contradictions that forward checking misses completely.

QUICK RECALL
  • Forward Checking: removes conflicting values from unassigned neighbors upon assignment.
  • Backtracks immediately if any neighbor's domain becomes empty.
  • MAC (Maintaining Arc Consistency): runs AC-3 after each assignment to detect multi-hop contradictions.

Minimax Algorithm

  • Terminal test returns utility.
  • $\text{Minimax}(s) = \max_a$ for MAX; $\min_a$ for MIN.
  • Time: $O(b^m)$ (exponential); Space: $O(bm)$ (linear).
  • Optimal against optimal opponent.

Alpha-Beta Pruning

  • $\alpha$: best for MAX ($-\infty$); $\beta$: best for MIN ($+\infty$).
  • Cutoff condition: $\mathbf{\beta \le \alpha}$.
  • Returns identical decision as Minimax.
  • Best-case complexity: $O(b^{m/2})$ (doubles depth).

CSP Model & AC-3

  • CSP = $\{X, D, C\}$.
  • Arc $(X_i, X_j)$ consistent $\iff \forall x \in D_i, \exists y \in D_j$ satisfying constraint.
  • AC-3 re-enqueues arcs entering $X_i$ if $D_i$ shrinks.
  • Complexity: $O(c d^3)$.

Backtracking Heuristics

  • MRV: pick variable with fewest legal values.
  • Degree: pick variable with most unassigned neighbors.
  • LCV: pick value ruling out fewest options for neighbors.
  • Forward Checking: prune neighbor domains; backtrack on empty domain.

PRACTICE 1 • BEST-CASE ALPHA-BETA

In a game with branching factor $b = 16$ and depth $m = 6$, how many leaf evaluations are saved by Alpha-Beta in the best case?

Show Step-by-Step Solution

Pure Minimax: $b^m = 16^6 = 16,777,216$ evaluations.

Best-case Alpha-Beta: $b^{m/2} = 16^3 = 4,096$ evaluations.

$$\text{Saved evaluations} = 16,777,216 - 4,096 = \mathbf{16,773,120\text{ leaf evaluations pruned!}}$$
PRACTICE 2 • CSP ARCS

In a CSP with 5 variables where every pair shares a binary constraint, how many directed arcs are placed in the AC-3 queue initially?

Show Step-by-Step Solution

Number of undirected edges in complete graph $K_5$: $\frac{5 \times 4}{2} = 10$.

Each undirected edge corresponds to two directed arcs $(X_i, X_j)$ and $(X_j, X_i)$:

$$\text{Total directed arcs} = 10 \times 2 = \mathbf{20\text{ arcs}}$$
