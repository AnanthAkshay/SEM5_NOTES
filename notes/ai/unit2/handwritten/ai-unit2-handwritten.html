Uninformed (Blind) Search Strategies

§ 1

Uninformed search (also termed blind search) refers to strategies that have no additional information about states beyond that provided in the problem definition. They can generate successors and distinguish a goal state from a non-goal state, but cannot estimate how close a non-goal state is to the destination.

1. Breadth-First Search (BFS)

BFS expands the shallowest unexpanded node first using a First-In First-Out (FIFO) queue frontier. All nodes at depth ddd are expanded before any nodes at depth d+1d + 1d+1.

  • Completeness: Yes (if branching factor bbb is finite).
  • Time Complexity: O(bd)O(b^d)O(bd), where bbb is the branching factor and ddd is the depth of the shallowest goal.
  • Space Complexity: O(bd)O(b^d)O(bd) — every generated node must remain in memory. Memory is the fatal bottleneck of BFS!
  • Optimality: Yes, if all step costs are equal; otherwise not necessarily optimal.

2. Uniform-Cost Search (UCS / Dijkstra on Trees)

UCS expands the node nnn with the lowest path cost g(n)g(n)g(n) from the start node using a Priority Queue ordered by g(n)g(n)g(n).

  • Goal Test Timing: The goal test is applied when a node is selected for expansion (popped from the priority queue), NOT when it is first generated!
  • Completeness: Yes, provided every step cost is strictly positive (c(s,a,s′)≥ϵ>0c(s, a, s') \ge \epsilon > 0c(s,a,s′)≥ϵ>0).
  • Time & Space Complexity: O(b1+⌊C∗/ϵ⌋)O(b^{1 + \lfloor C^* / \epsilon \rfloor})O(b1+⌊C∗/ϵ⌋), where C∗C^*C∗ is the cost of the optimal solution and ϵ\epsilonϵ is the minimal step cost.
  • Optimality: Yes! UCS is guaranteed to find the cheapest path for arbitrary non-negative step costs.

3. Depth-First Search (DFS)

DFS expands the deepest unexpanded node first using a Last-In First-Out (LIFO) stack frontier.

  • Completeness: No in infinite-depth spaces or spaces with loops (unless cycle-checking graph search is used); Yes in finite state spaces.
  • Time Complexity: O(bm)O(b^m)O(bm), where mmm is the maximum depth of the state space (m≫dm \gg dm≫d).
  • Space Complexity: O(bm)O(bm)O(bm) — only needs to store a single path from the root to a leaf plus unexpanded sibling nodes. Linear memory advantage!
  • Optimality: No — it can return a deeply nested suboptimal goal before exploring a shallow optimal one.

4. Iterative Deepening Depth-First Search (IDDFS)

IDDFS solves the dilemma between BFS (optimal, but exponential memory) and DFS (linear memory, but non-optimal and incomplete). It repeatedly runs Depth-Limited Search (DLS) with increasing depth limits (l=0,1,2,3,…,dl = 0, 1, 2, 3, \dots, dl=0,1,2,3,…,d).

WHY IDDFS IS THE PREFERRED UNINFORMED SEARCH METHOD

Although it appears wasteful to re-generate nodes from earlier depths, the bottom layer dominates the expansion cost in exponential trees. The number of generated nodes in IDDFS is:

N(IDDFS)=(d)b1+(d−1)b2+⋯+(1)bd=O(bd)N(\text{IDDFS}) = (d)b^1 + (d-1)b^2 + \dots + (1)b^d = O(b^d)N(IDDFS)=(d)b1+(d−1)b2+⋯+(1)bd=O(bd)

For b=10,d=5b = 10, d = 5b=10,d=5, BFS generates 111,111 nodes while IDDFS generates 123,450 nodes (only ~11% overhead!). IDDFS combines the completeness and optimality of BFS with the modest O(bd)O(bd)O(bd) linear memory storage of DFS.

QUICK RECALL
  • BFS: FIFO queue, O(bd)O(b^d)O(bd) time & space, optimal for unit costs. Space is the killer.
  • UCS: Priority queue ordered by g(n)g(n)g(n), goal test on POP, optimal for non-negative costs.
  • DFS: LIFO stack, O(bm)O(bm)O(bm) linear space, not optimal, incomplete on infinite trees.
  • IDDFS: Runs DLS with limit 0,1,2,…,d0, 1, 2, \dots, d0,1,2,…,d. Combines BFS optimality with DFS O(bd)O(bd)O(bd) linear space!

Informed Search & Heuristic Functions

§ 3

Informed search strategies utilize problem-specific knowledge beyond the problem definition via a heuristic function h(n)h(n)h(n), enabling the search to prune barren paths and focus exploration directly toward the goal.

HEURISTIC FUNCTION DEFINITION

A heuristic function h(n)h(n)h(n) estimates the cost of the cheapest path from the state at node nnn to a goal state:

A∗A^*A∗ Search: Conditions for Optimality (Admissibility & Consistency)

§ 4

A∗A^*A∗ is the most widely celebrated search algorithm in computer science. However, its guarantee of optimality relies strictly on mathematical conditions governing the heuristic function.

1. ADMISSIBILITY (REQUIRED FOR TREE SEARCH)

An admissible heuristic is one that never overestimates the true cost to reach the goal. That is, h(n)h(n)h(n) is optimistic:

h(n)≤h∗(n)∀n\mathbf{h(n) \le h^*(n) \quad \forall n}h(n)≤h∗(n)∀n

where h∗(n)h^*(n)h∗(n) is the true, optimal cost to reach the nearest goal from nnn.

Theorem: If h(n)h(n)h(n) is admissible, A∗A^*A∗ using Tree-Search is guaranteed to return an optimal solution.

2. CONSISTENCY / MONOTONICITY (REQUIRED FOR GRAPH SEARCH)

A heuristic h(n)h(n)h(n) is consistent (or monotonic) if, for every node nnn and every successor n′n'n′ generated by action aaa:

h(n)≤c(n,a,n′)+h(n′)\mathbf{h(n) \le c(n, a, n') + h(n')}h(n)≤c(n,a,n′)+h(n′)

Geometric Intuition: This is a form of the Triangle Inequality. The estimated cost from nnn to the goal cannot exceed the step cost to step n′n'n′ plus the estimated cost from n′n'n′ to the goal.

Theorem: If h(n)h(n)h(n) is consistent, A∗A^*A∗ using Graph-Search is guaranteed to be optimal. Furthermore, the first time A∗A^*A∗ expands any node nnn, the path to nnn is guaranteed to be optimal; hence nodes placed on the Closed list never need to be reopened!

RELATIONSHIP BETWEEN ADMISSIBILITY & CONSISTENCY

Every consistent heuristic is admissible (Consistency  ⟹  AdmissibilityConsistency \implies AdmissibilityConsistency⟹Admissibility). While an admissible heuristic can occasionally be inconsistent in rare contrived graphs, virtually all natural heuristics derived from relaxed problems are automatically consistent.

Heuristics for the 8-Puzzle & Heuristic Dominance

§ 5

A standard method for generating admissible heuristics is to compute the exact cost of a solution to a relaxed problem (a problem with fewer restrictions on the actions).

Two Classical 8-Puzzle Heuristics

  1. h1(n)h_1(n)h1​(n) — Number of Misplaced Tiles:

    Count the number of tiles that are not in their goal position. (If a tile can move anywhere instantly, each misplaced tile needs at least 1 move). Clearly admissible: h1(n)≤h∗(n)h_1(n) \le h^*(n)h1​(n)≤h∗(n).

  2. h2(n)h_2(n)h2​(n) — Manhattan Distance (City Block Distance):

    The sum of the horizontal and vertical distances of each tile from its target goal position:

    h2(n)=∑i=18(∣xi−xi,goal∣+∣yi−yi,goal∣)h_2(n) = \sum_{i=1}^{8} \left( |x_i - x_{i,\text{goal}}| + |y_i - y_{i,\text{goal}}| \right)h2​(n)=i=1∑8​(∣xi​−xi,goal​∣+∣yi​−yi,goal​∣)

    Admissible because each move can reduce the Manhattan distance of at most one tile by at most 1.

HEURISTIC DOMINANCE

If h2(n)≥h1(n)h_2(n) \ge h_1(n)h2​(n)≥h1​(n) for all nodes nnn, and both are admissible, we say that h2h_2h2​ dominates h1h_1h1​.

Consequence: A∗A^*A∗ using h2h_2h2​ will never expand more nodes than A∗A^*A∗ using h1h_1h1​ (except possibly for some nodes on the boundary where f(n)=C∗f(n) = C^*f(n)=C∗). A dominating heuristic translates directly to greater pruning power and faster search!

For the 8-puzzle: since Manhattan distance counts the minimum moves for each tile to reach home and each misplaced tile is at least 1 step away, h2(n)≥h1(n)h_2(n) \ge h_1(n)h2​(n)≥h1​(n) always holds. Manhattan distance strictly dominates misplaced tiles.

QUICK RECALL
  • Relaxed problem: removing constraints yields admissible heuristics.
  • 8-puzzle: h1h_1h1​ = misplaced tiles; h2h_2h2​ = Manhattan distance (∑∣Δx∣+∣Δy∣\sum |\Delta x| + |\Delta y|∑∣Δx∣+∣Δy∣).
  • h2h_2h2​ dominates h1  ⟺  h2(n)≥h1(n)  ⟹  h2h_1 \iff h_2(n) \ge h_1(n) \implies h_2h1​⟺h2​(n)≥h1​(n)⟹h2​ expands fewer nodes.

Local Search Algorithms & Optimization

§ 6

In many problems (such as the 8-queens, VLSI circuit layout, or factory scheduling), the path to the goal is completely irrelevant; only the final goal state itself matters. Local search algorithms operate using a single current state (rather than multiple paths) and generally move only to neighbors of that state, requiring O(1)O(1)O(1) constant memory.

State Space Landscape & Local Search Hazards

Hill-Climbing Search (Greedy Local Search)

Hill-climbing simply loops continuously in the direction of increasing value (uphill). It terminates when it reaches a peak where no neighbor has a higher value.

THREE CLASSIC FAILURE MODES OF HILL CLIMBING
  1. Local Maxima: A peak that is higher than each of its neighbors, but lower than the global maximum. The algorithm terminates prematurely.
  2. Ridges: A sequence of local maxima where the slope gently rises along a diagonal ridge, but the allowable orthogonal moves all lead downhill.
  3. Plateaux: A flat area of the state space landscape where all neighbors have the identical value. The algorithm wanders aimlessly in a random walk.

Remedy — Random-Restart Hill Climbing: Conducts a series of hill-climbing searches from randomly generated initial states until a goal is found. Theorem: If each hill-climb has probability ppp of success, expected number of restarts is 1/p1/p1/p. Trivially complete with probability 1!

QUICK RECALL
  • Local search operates on complete-state representations with O(1)O(1)O(1) memory.
  • Hill climbing moves greedily uphill; gets stuck on local maxima, ridges, and plateaux.
  • Random-Restart Hill Climbing guarantees finding global optimum given sufficient restarts.

Simulated Annealing & Genetic Algorithms

§ 7

To escape local maxima, an algorithm must occasionally make downhill moves. Two primary nature-inspired stochastic optimization methods achieve this: Simulated Annealing (thermodynamics) and Genetic Algorithms (biological evolution).

1. Simulated Annealing

Inspired by the metallurgical process of annealing (heating metal to high temperatures and cooling it slowly to form a crystal with minimal energy defects).

SIMULATED ANNEALING ALGORITHM

2. Genetic Algorithms (GAs)

A variant of stochastic beam search where successor states are generated by combining two parent states (crossover) rather than modifying a single state.

1
Representation: A state is encoded as a string over a finite alphabet (a chromosome / string of digits, e.g. 8-queens encoded as an 8-digit string indicating the row position of queen in each column).
2
Fitness Function: Evaluates the quality of each state (e.g. number of non-attacking queen pairs, maximum = 28).
3
Selection: Pairs of individuals are chosen for reproduction with probability proportional to their fitness (Roulette-wheel selection).
4
Crossover: A random crossover point is chosen. Offspring inherit the first segment from parent 1 and the remainder from parent 2.
5
Mutation: Each bit/digit is randomly mutated with a small independent probability (e.g. 1%) to maintain genetic diversity.
QUICK RECALL
  • Simulated Annealing accepts downhill moves with probability P=eΔE/TP = e^{\Delta E / T}P=eΔE/T. High TTT = random walk; Low TTT = greedy hill climb.
  • Genetic Algorithms: Population, Fitness proportional selection, Crossover, Mutation.
  • 8-queens can be encoded as an 8-character string with fitness = non-attacking pairs.

Ans

1. Inspiration & Algorithmic Framework:

Adapted from metallurgical annealing (gradual cooling of molten metals to reach low-energy crystalline states), Simulated Annealing escapes local maxima by combining greedy hill-climbing with stochastic exploration.

2. Downhill Move Acceptance Rule:

  • At state sss, pick a random neighboring state s′s's′. Compute energy difference ΔE=E(s′)−E(s)\Delta E = E(s') - E(s)ΔE=E(s′)−E(s).
  • If ΔE>0\Delta E > 0ΔE>0 (uphill move towards improvement), the move is always accepted.
  • If ΔE≤0\Delta E \le 0ΔE≤0 (downhill move), the move is accepted probabilistically with Boltzmann probability: P=eΔE/TP = e^{\Delta E / T}P=eΔE/T where T>0T > 0T>0 is the current temperature parameter.

3. Role of Temperature (TTT) and Cooling Schedule:

  • Initial High Temperature (T≫0T \gg 0T≫0): When TTT is very large, \Delta E / T pprox 0 \implies P pprox e^0 = 1. The search accepts almost all downhill moves, behaving like a random walk that freely explores the entire landscape without getting trapped.
  • Cooling Progression (T_{k+1} = lpha T_k, 0.8 \le lpha \le 0.99): As TTT decreases, the probability PPP of accepting worse moves drops exponentially. The agent becomes increasingly selective, accepting only shallow downhill moves.
  • Freezing Phase (To0T o 0To0): As To0T o 0To0, Po0P o 0Po0. Downhill moves are strictly rejected, and the algorithm smoothly degenerates into standard greedy hill-climbing, locking cleanly into the nearest global peak.

  • If the goal test were applied when a node is generated, UCS could stop immediately upon discovering the first path to the goal.
  • However, that first path might have a high step cost (e.g., SoGS o GSoG with cost 10). A much cheaper path might exist (e.g., SoAoBoGS o A o B o GSoAoBoG with total cost 1+1+1=31+1+1 = 31+1+1=3), but its intermediate nodes have not yet been expanded!
  • By testing for the goal only when a node is popped for expansion, UCS guarantees that all nodes with path cost less than g(G)g(G)g(G) have already been expanded. This ensures that when GGG is popped, no cheaper path to GGG can possibly exist, preserving mathematical optimality.
