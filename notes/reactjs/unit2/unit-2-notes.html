1. Functional vs. Class Components

Definition

A React Component is a self-contained, reusable piece of user interface that accepts inputs (props) and returns a React element tree (JSX) describing what should appear on the screen.

1.1 Functional Components (Modern Industry Standard)

A functional component is simply a JavaScript function that accepts a single props object as an argument and returns JSX. With the introduction of React Hooks (React 16.8+), functional components possess all capabilities previously restricted to classes, including local state and lifecycle side-effects:

jsx 
// Modern Functional Component
export default function WelcomeBanner({ username }) {
  return (
    <div className="banner">
      <h1>Welcome to SEM5 Portal, {username}!</h1>
    </div>
  );
}

1.2 Class Components (Overview & Legacy Codebases)

Before React Hooks, class components were required whenever a component needed internal state or lifecycle methods. A class component extends React.Component and implements a mandatory render() method:

jsx 
// Legacy Class Component
import React, { Component } from 'react';

class WelcomeBannerClass extends Component {
  render() {
    // Props are accessed via this.props
    return (
      <div className="banner">
        <h1>Welcome to SEM5 Portal, {this.props.username}!</h1>
      </div>
    );
  }
}
export default WelcomeBannerClass;
Feature Functional Components Class Components (Legacy)
Syntax Plain JavaScript function. ES6 class extending React.Component.
Props Access Directly via function arguments: props.name or ({ name }). Via class instance: this.props.name.
State Management Using the useState hook. Via this.state = {...} and this.setState().
this Keyword Binding None (no this confusion!). Requires manual method binding (this.handleClick.bind(this)).
Code Conciseness High (less boilerplate, easier to test and compose). Low (verbose constructor, render method).
Quick Recall

Functional components are plain JS functions returning JSX and managed via Hooks. Class components extend React.Component, access props via this.props, and require a render() method.

2. Passing & Accessing Props

Definition

Props (short for Properties) are read-only configuration inputs passed from a parent component down to a child component, analogous to HTML attributes or function arguments.

2.1 Pure Functions & Props Immutability Rule

Fundamental Rule of React

All React components must act like pure functions with respect to their props. A component must NEVER mutate its own props (e.g. props.score = 100 is strictly forbidden and triggers runtime errors or unpredictability).

2.2 Destructuring Props with Default Values

Instead of typing props.title throughout the component body, modern React idiomatically destructures props in the function parameter list with fallback default values:

jsx 
// Parent Component
function CourseDirectory() {
  return (
    <div>
      {/* Passing different prop types: string, number, boolean, object */}
      <CourseCard 
        title="Front End Development using ReactJS" 
        code="ISAEC594" 
        credits={1} 
        isElective={true}
      />
      <CourseCard 
        title="Machine Learning" 
        code="IS51" 
        credits={4} 
        isElective={false}
      />
    </div>
  );
}

// Child Component with Destructuring and Default Values
function CourseCard({ title, code, credits = 3, isElective = false }) {
  return (
    <div className="course-card">
      <h3>{title} ({code})</h3>
      <p>Credits: {credits} | Type: {isElective ? "Elective" : "Core"}</p>
    </div>
  );
}
Quick Recall

Props are immutable inputs passed from parent to child. Components must never mutate props. Destructure props in parameter lists with default values: ({ title, credits = 3 }).

3. Props vs. State (Comparative Analysis)

A classic exam question asks students to contrast Props and State across ownership, mutability, and architectural intent:

Dimension Props (Properties) State
Origin & Ownership Passed from parent component (External). Created and managed internally inside the component (Internal).
Mutability Immutable (Read-Only) from the child's perspective. Mutable via its dedicated setter function (setState).
Purpose Configuring child components; passing data and event callbacks downward. Tracking dynamic data that changes over time based on user interactions (clicks, inputs).
Re-render Trigger Child re-renders when parent passes new prop values. Component re-renders whenever its state setter function is called with a new value.
Analogy Function arguments passed into a function. Local variables declared inside the function body.
Quick Recall

Props = external, read-only data passed from parents. State = internal, dynamic data managed by the component itself via setter functions.

4. React Fragments (<>...</>)

Definition

A React Fragment allows a component to group a list of multiple adjacent children without adding extra wrapper nodes (such as unnecessary <div> elements) to the real DOM.

4.1 Why Are Fragments Necessary?

  • Semantic HTML Integrity: Adding an extraneous <div> inside a table row (<tr>) or a flexbox/grid container breaks HTML validation and CSS layout flow:
    jsx
    // INVALID HTML: A <div> cannot be a direct child of <tr>!
function TableColumns() {
  return (
    <div>
      <td>IS51</td>
      <td>Machine Learning</td>
    </div>
  );
}

// VALID WITH FRAGMENTS: No extra DOM node injected!
function TableColumns() {
  return (
    <>
      <td>IS51</td>
      <td>Machine Learning</td>
    </>
  );
}
  • Keyed Fragments: When mapping a list of fragments inside a loop, use the explicit <React.Fragment key={item.id}> syntax because the short syntax (<>) cannot take attributes.
Quick Recall

Fragments (<>...</>) group children without inserting redundant wrapper elements into the DOM tree. Use <React.Fragment key={id}> when keys are required.

5. Component Composition & props.children

Definition

props.children is a special built-in prop in React that represents whatever JSX markup or child components are nested between an opening and closing component tag.

React favors composition over inheritance. Instead of creating complex class inheritance hierarchies, developers create generic "box" or "container" components that receive nested content through children:

jsx 
// 1. Generic Container Component (Card)
function Card({ title, borderColor = "#ccc", children }) {
  return (
    <div className="card-container" style={{ border: `2px solid ${borderColor}`, padding: "16px", borderRadius: "10px" }}>
      <div className="card-header">
        <h3>{title}</h3>
      </div>
      {/* Renders whatever JSX was placed between <Card> and </Card> */}
      <div className="card-body">
        {children}
      </div>
    </div>
  );
}

// 2. Using the Card Component with Arbitrary Content
function Dashboard() {
  return (
    <Card title="Examination Alert" borderColor="#d9534f">
      <p>CIE-1 for 5th Semester begins on 20th October!</p>
      <button className="btn-alert">Download Time Table</button>
    </Card>
  );
}
Quick Recall

props.children enables component composition: whatever JSX is nested inside <Component>children here</Component> is accessible to the component via props.children.

6. State Management with the useState Hook

Definition

useState is the foundational React Hook that allows functional components to declare and retain local state variables across re-renders.

6.1 Hook Syntax & Array Destructuring

The useState function returns an array containing exactly two items:

$$\mathbf{[stateVariable, \ setstateVariable] = \text{useState}(initialValue);}$$
  1. stateVariable: The current state value during this render.
  2. setstateVariable: A setter function used to update the state and schedule a component re-render.

6.2 Direct Updates vs. Functional (Updater) Updates

jsx 
import { useState } from 'react';

function Counter() {
  const [count, setCount] = useState(0);

  // Direct Update: Safe when new state does not depend on current state
  const resetCount = () => {
    setCount(0);
  };

  // Functional Update: MANDATORY when new state depends on previous state!
  const incrementByThree = () => {
    // If you wrote:
    // setCount(count + 1);
    // setCount(count + 1);
    // setCount(count + 1);
    // All three read the same stale snapshot of 'count' (e.g. 0), resulting in count = 1!

    // PASSING AN UPDATER FUNCTION: Guarantees latest state from queue!
    setCount(prevCount => prevCount + 1); // 0 + 1 = 1
    setCount(prevCount => prevCount + 1); // 1 + 1 = 2
    setCount(prevCount => prevCount + 1); // 2 + 1 = 3 -> Correct!
  };

  return (
    <div>
      <h2>Count: {count}</h2>
      <button onClick={() => setCount(count + 1)}>+1</button>
      <button onClick={incrementByThree}>+3 (Batch Safe)</button>
      <button onClick={resetCount}>Reset</button>
    </div>
  );
}
Quick Recall

const [state, setState] = useState(initial);. Always use functional updates setState(prev => prev + 1) when the new state depends on the previous state to prevent stale batching bugs.

7. Immutable State Updates (Objects & Arrays)

In React, state should be treated as strictly read-only. Never mutate objects or arrays in-place (e.g., user.age = 22 or items.push(newItem)), because React performs an object reference identity check (Object.is(oldState, newState)). If the memory reference has not changed, React assumes nothing was modified and skips re-rendering!

7.1 Updating Objects via the Spread Operator (...)

jsx 
const [profile, setProfile] = useState({ name: "Kavya", semester: 5, cgpa: 9.1 });

// WRONG: Mutates state in place! Component will NOT re-render!
// profile.cgpa = 9.3;
// setProfile(profile);

// CORRECT: Create a shallow copy and override specific fields
const updateCgpa = (newCgpa) => {
  setProfile(prevProfile => ({
    ...prevProfile,      // Copy all existing fields (name, semester)
    cgpa: newCgpa        // Override the target property
  }));
};

7.2 Updating Arrays Immutably

Operation Mutating Method (DO NOT USE in React) Immutable Idiomatic Replacement (USE THIS)
Add Item arr.push(item), arr.unshift(item) Spread syntax: [...arr, item] or [item, ...arr]
Remove Item arr.splice(index, 1), arr.pop() Filter method: arr.filter(item => item.id !== targetId)
Update Item arr[index] = newItem Map method: arr.map(item => item.id === targetId ? { ...item, done: true } : item)
Sort / Reverse arr.sort(), arr.reverse() (mutates original!) Copy first: [...arr].sort(...)
Quick Recall

Never mutate state in-place. Copy objects using spread { ...prev, field: val }. Modify arrays using immutable methods: spread to add, .filter() to delete, .map() to update.

8. Tested Component Implementations

Complete Tested Component: Study Task Tracker with Array State

This runnable component demonstrates functional state management, array addition via spread, and deletion via .filter():

jsx 
import { useState } from 'react';

export default function StudyTracker() {
  const [tasks, setTasks] = useState([
    { id: 1, text: "Review ML Unit 1 Notes", priority: "High" },
    { id: 2, text: "Practice TOC DFA Minimization", priority: "Medium" }
  ]);
  const [inputVal, setInputVal] = useState("");

  // Handler: Add new task immutably using spread operator
  const handleAddTask = () => {
    if (!inputVal.trim()) return;
    const newTask = {
      id: Date.now(), // Unique ID for key prop
      text: inputVal.trim(),
      priority: "Normal"
    };
    setTasks(prevTasks => [...prevTasks, newTask]);
    setInputVal(""); // Reset input field
  };

  // Handler: Remove task immutably using .filter()
  const handleDeleteTask = (idToDelete) => {
    setTasks(prevTasks => prevTasks.filter(task => task.id !== idToDelete));
  };

  return (
    <div className="tracker-card" style={{ padding: "20px", border: "1px solid #ddd", borderRadius: "10px" }}>
      <h3>V Semester Study Goals ({tasks.length} Pending)</h3>
      
      <div style={{ display: "flex", gap: "8px", marginBottom: "16px" }}>
        <input 
          type="text" 
          value={inputVal} 
          onChange={(e) => setInputVal(e.target.value)} 
          placeholder="Enter exam study topic..."
          style={{ flexGrow: 1, padding: "8px" }}
        />
        <button onClick={handleAddTask} style={{ padding: "8px 16px" }}>Add Task</button>
      </div>

      <ul style={{ listStyle: "none", padding: 0 }}>
        {tasks.map((task) => (
          <li key={task.id} style={{ display: "flex", justifyContent: "space-between", padding: "8px 0", borderBottom: "1px solid #eee" }}>
            <span>📌 {task.text} <em style={{ color: "#888" }}>({task.priority})</em></span>
            <button onClick={() => handleDeleteTask(task.id)} style={{ color: "red", cursor: "pointer" }}>✕ Done</button>
          </li>
        ))}
      </ul>
    </div>
  );
}

Step-by-Step Click Trace:

  1. User types "Learn React Hooks" → onChange fires → setInputVal updates inputVal → input element re-renders displaying text.
  2. User clicks "Add Task" → handleAddTask creates new object with id: Date.now() → setTasks([...prev, newTask]) schedules re-render → list updates to 3 tasks.
  3. User clicks "✕ Done" on task 1 → handleDeleteTask(1) runs filter(t => t.id !== 1) → task 1 removed → state now contains remaining 2 tasks.

10. Important Exam Questions & Practice

The following conceptual questions and verified code tracing problems cover essential university examination patterns for ISAEC594 (Front End Development using ReactJS):

2-Mark Conceptual Questions

2 MARKS 1. Differentiate between Props and State in React.

Answer:

  • Props (Properties): External, read-only configuration passed from a parent component downward to a child. They are immutable from the child component's perspective.
  • State: Internal, private data managed locally within a component via the useState hook. When state transitions occur via its setter function, React schedules a re-render of the component and its children.
2 MARKS 2. What are React Fragments and why are they used?

Answer:

React Fragments (<>...</> or <React.Fragment>...</React.Fragment>) allow grouping a list of children elements without adding an extra wrapper node (such as an unwanted <div>) to the browser's real DOM tree.

Use Cases: Preserves semantic HTML layouts such as tables (e.g. returning multiple <td> elements inside a table row) and CSS Flexbox/Grid parent-child alignments.

2 MARKS 3. Explain the purpose of `props.children` with a brief example.

Answer:

props.children is a special prop available in every React component that automatically captures any JSX elements or text passed between the component's opening and closing tags.

Example: In <Card><h2>Title</h2></Card>, the Card component receives the <h2> node inside props.children, enabling flexible container composition patterns.

2 MARKS 4. State the two fundamental Rules of Hooks in React.

Answer:

  1. Only Call Hooks at the Top Level: Do not call hooks inside loops, conditional statements (if), or nested functions. This ensures hooks are invoked in the exact same sequential order on every render, allowing React to correctly preserve state associations.
  2. Only Call Hooks from React Functions: Only invoke hooks from React functional components or custom hooks, never from regular JavaScript utility functions or class components.
2 MARKS 5. Why should functional state updates `setState(prev => prev + 1)` be used instead of direct updates `setState(state + 1)`?

Answer:

React batches multiple state updates during event handlers and asynchronous operations for performance. Direct updates read the current render's stale closure snapshot of state. If multiple direct updates are executed in succession, subsequent calls overwrite previous ones. Passing an updater callback function prev => prev + 1 guarantees React passes the most recent pending state to the calculation.

5-Mark & 10-Mark Model Questions

10 MARKS 6. Explain the `useState` hook in React with syntax, mechanics, and a complete working counter implementation.

Comprehensive Answer:

  1. Hook Definition & Signature: const [state, setState] = useState(initialValue);
    useState is a built-in React Hook enabling functional components to maintain private, local reactive state. It takes an optional initial value and returns an array of two items using ES6 array destructuring:
    • state: The current state variable.
    • setState: The dispatcher function used to update the state and trigger a re-render.
  2. Update Mechanics & Batching: When setState is called, React does not mutate the variable immediately in place. Instead, it enqueues a re-render request with the new value. React compares the new value with the old value using Object.is equality; if unchanged, React bails out of re-rendering.
  3. Complete Working Implementation: 
    import React, { useState } from 'react';

export default function Counter() {
  const [count, setCount] = useState(0);

  return (
    <div className="counter-card">
      <h2>Current Count: {count}</h2>
      <button onClick={() => setCount(prev => prev + 1)}>Increment</button>
      <button onClick={() => setCount(prev => Math.max(0, prev - 1))}>Decrement</button>
      <button onClick={() => setCount(0)}>Reset</button>
    </div>
  );
}
10 MARKS 7. Why is state immutability crucial in React? Explain how objects and arrays are immutably updated with clear code examples.

Crucial Nature of State Immutability:

React relies on shallow reference comparison (Object.is) to detect whether state has updated. If an object or array is mutated directly in-place (e.g. user.age = 21 or arr.push(item)), the memory pointer/reference of the object remains identical. React perceives no change and will skip re-rendering the component, leading to silent UI synchronization failures.

Immutable Modification Patterns:

  • 1. Updating Objects: Always copy the existing object using the ES6 object spread operator (...) and override specific fields: 
    // Correct: Creates a brand new object reference
setUser(prevUser => ({
  ...prevUser,
  age: prevUser.age + 1
}));
  • 2. Adding Items to Arrays: Use array spread syntax instead of push(): 
    setItems(prev => [...prev, newItem]);
  • 3. Deleting Items from Arrays: Use Array.prototype.filter() which returns a new filtered array: 
    setItems(prev => prev.filter(item => item.id !== idToDelete));
  • 4. Updating Items in Arrays: Use Array.prototype.map() to produce a transformed array copy: 
    setItems(prev => prev.map(item => 
  item.id === targetId ? { ...item, completed: true } : item
));
