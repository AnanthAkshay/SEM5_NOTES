Explain the role of ReactDOM in connecting React components with the browser DOM.

Model Exam Answer

1. Role of ReactDOM

ReactDOM acts as the bridge or rendering engine between React's declarative component tree (Virtual DOM) and the actual browser Document Object Model (Real DOM).

  • Root Creation and Mounting: In modern React 18+, ReactDOM.createRoot(container) initializes a React root on an existing HTML container node (usually <div id="root"></div>).
  • Rendering Virtual Trees: root.render(<App />) takes the top-level React element, evaluates its component tree, and builds the in-memory Virtual DOM representation.
  • DOM Reconciliation & Commit: When state changes, ReactDOM receives the reconciliation diff from React and efficiently performs the minimum necessary DOM mutations (insertions, updates, deletions) using browser DOM APIs (like document.createElement, appendChild).
  • Portals Support: ReactDOM.createPortal(child, domNode) allows rendering components into a DOM node outside the parent component's DOM hierarchy (critical for modals, tooltips, dialogs).
import React from 'react';
import ReactDOM from 'react-dom/client';
import App from './App';

const root = ReactDOM.createRoot(document.getElementById('root'));
root.render(<App />);

Explain how JSX is compiled internally with Babel transformations.

Model Exam Answer

1. JSX Compilation Process

Browsers cannot understand JSX directly because it is not standard ECMAScript. During the build process, a JavaScript compiler such as Babel transforms JSX into plain JavaScript function calls.

2. Classic Runtime: React.createElement

Each JSX tag compiles into a call to React.createElement(type, props, ...children):

  • Type: A string for HTML tags ('div', 'h1') or a function/class reference for custom components (App).
  • Props: An object containing all attributes and event handlers (or null if none).
  • Children: Any nested JSX elements, text strings, or expressions passed as rest parameters.

3. Transformation Example:

Input JSX:

const element = (
  <div className="card">
    <h1>Welcome</h1>
    <p>Hello Aki</p>
  </div>
);

Babel Transpiled Output:

const element = React.createElement(
  'div',
  { className: 'card' },
  React.createElement('h1', null, 'Welcome'),
  React.createElement('p', null, 'Hello Aki')
);

This produces a lightweight Virtual DOM JavaScript object with properties: { $$typeof: Symbol(react.element), type: 'div', props: { className: 'card', children: [...] } }.

Discuss JSX syntax rules with suitable examples.

Model Exam Answer

Fundamental Rules of JSX Syntax

  1. Single Root Element: Every JSX expression must return a single top-level parent element. Multiple sibling elements must be wrapped in a container tag (e.g. <div>) or a React Fragment (<>...</>):
    // Correct:
return (
  <>
    <h1>Header</h1>
    <p>Paragraph</p>
  </>
);
  2. Close All Tags: All elements must be explicitly closed. Self-closing tags must end with />:
    <img src="logo.png" alt="Logo" />
<input type="text" />
<br />
  3. camelCase Property Naming: Because JSX compiles to JavaScript objects, HTML attribute names that collide with JS reserved words use camelCase:
    • class $\rightarrow$ className
    • for $\rightarrow$ htmlFor
    • tabindex $\rightarrow$ tabIndex
    • onclick $\rightarrow$ onClick
  4. JavaScript Expressions in Curly Braces: Any valid JavaScript variable, function call, or expression can be embedded inside { }:
    const user = 'Aki';
return <h2>Hello, {user.toUpperCase()}!</h2>;
  5. Inline Style Objects: Styles are written as JavaScript objects with camelCase keys:
    <div style={{ backgroundColor: '#1e293b', padding: '10px' }}>Card</div>

📖 Theory Link: Unit 1 § 6

Explain how state flows inside a React application with an example.

Model Exam Answer

1. One-Way Data Flow (Unidirectional Flow)

In React, state follows a strict top-down (unidirectional) data flow:

  • Single Source of Truth: State is owned and maintained by a specific component.
  • Downward Flow: State is passed down to child components exclusively via props. Child components cannot directly alter parent state.
  • Upward Communication via Callbacks: If a child needs to trigger a state change, the parent passes down a callback function via props. The child invokes the callback with updated values, allowing the parent to update its own state, triggering a clean re-render cycle.

2. Illustrative Example

import React, { useState } from 'react';

// Child component receives value and update handler
function ToggleButton({ isOn, onToggle }) {
  return (
    <button onClick={onToggle}>
      Status: {isOn ? 'ACTIVE' : 'INACTIVE'}
    </button>
  );
}

// Parent holds state and passes it down
function App() {
  const [isActive, setIsActive] = useState(false);

  const handleToggle = () => {
    setIsActive(prev => !prev); // Parent updates state
  };

  return (
    <div>
      <h3>Parent State: {isActive ? 'Running' : 'Stopped'}</h3>
      <ToggleButton isOn={isActive} onToggle={handleToggle} />
    </div>
  );
}

What is the Virtual DOM in React? Explain how the Reconciliation Diffing algorithm optimizes UI performance.

Model Exam Answer

1. Definition of Virtual DOM

The Virtual DOM (VDOM) is a lightweight, in-memory JavaScript object representation of the real browser DOM. Directly manipulating the real DOM is slow and expensive because each mutation triggers layout recalculation, style recalculation, and page re-rendering (reflow and repaint).

2. The Reconciliation Diffing Algorithm ($O(n)$)

When component state changes, React creates a new Virtual DOM snapshot and compares it with the previous snapshot. React achieves an $O(n)$ heuristic comparison based on two key assumptions:

  1. Different Element Types Produce Different Trees: If a root element changes type (e.g. from <div> to <span>), React unmounts the entire old tree and mounts a new tree from scratch without attempting to diff children.
  2. Keys Identify Stable Children: When list items change, React uses unique key props to match children across renders, determining whether an item was inserted, deleted, or reordered without tearing down all nodes.

3. Batching & Patching

React calculates the minimal set of changes (the "diff") and applies them in a single batched update to the real DOM, ensuring 60 FPS UI responsiveness.

Describe event bubbling in React with an example.

Model Exam Answer

1. Event Bubbling in React & SyntheticEvent

In standard DOM event propagation, an event triggered on a deeply nested element bubbles up through its ancestors in the DOM tree. React implements a cross-browser wrapper called SyntheticEvent and attaches top-level event listeners to the root container.

  • When an event fires on a child (e.g. button click), the event bubbles upwards through React's Virtual DOM hierarchy.
  • Parent handlers on the path are invoked unless explicitly stopped via e.stopPropagation().

2. Code Example

import React from 'react';

function BubblingDemo() {
  const handleParentClick = () => {
    alert('Parent DIV clicked (Bubbled up)!');
  };

  const handleChildClick = (e) => {
    alert('Child BUTTON clicked!');
    // Uncomment line below to prevent event from bubbling to parent:
    // e.stopPropagation();
  };

  return (
    <div onClick={handleParentClick} style={{ padding: '20px', background: '#e2e8f0' }}>
      <p>Parent Container</p>
      <button onClick={handleChildClick}>Click Me</button>
    </div>
  );
}

Clicking the button triggers "Child BUTTON clicked!" first, followed by "Parent DIV clicked (Bubbled up)!".

Build a functional component where users can type into an input box, and the app displays the current character count below it.

Model Exam Answer

1. Component Implementation

import React, { useState } from 'react';

function CharacterCounter() {
  const [text, setText] = useState('');
  const maxLimit = 100;

  const handleChange = (e) => {
    setText(e.target.value);
  };

  const charCount = text.length;
  const isOverLimit = charCount > maxLimit;

  return (
    <div style={{ maxWidth: '400px', padding: '16px', fontFamily: 'sans-serif' }}>
      <label htmlFor="user-input" style={{ fontWeight: 'bold', display: 'block', marginBottom: '6px' }}>
        Enter your text:
      </label>
      <input
        id="user-input"
        type="text"
        value={text}
        onChange={handleChange}
        placeholder="Type something..."
        style={{
          width: '100%',
          padding: '8px 12px',
          borderRadius: '6px',
          border: `1px solid ${isOverLimit ? '#ef4444' : '#cbd5e1'}`,
          boxSizing: 'border-box'
        }}
      />
      <div style={{
        marginTop: '8px',
        fontSize: '0.88rem',
        color: isOverLimit ? '#ef4444' : '#64748b',
        display: 'flex',
        justifyContent: 'space-between'
      }}>
        <span>Characters: <strong>{charCount}</strong></span>
        <span>Remaining: <strong>{maxLimit - charCount}</strong></span>
      </div>
    </div>
  );
}

export default CharacterCounter;

2. Key Mechanics

  • The text state is bound directly to the input's value (Controlled Input).
  • The onChange listener extracts e.target.value and updates state on every keystroke.
  • The character count is derived reactively via text.length without needing duplicate state.

Discuss handling inputs like checkbox, and textarea with examples.

Model Exam Answer

1. Handling Diverse Form Inputs in React

In React, all form inputs become controlled components when their display value is tied to React state and updated via an onChange handler.

  • Textarea: In HTML, <textarea> takes text between tags. In React, it uses a value prop identically to single-line text inputs.
  • Checkbox: Controlled using the checked boolean attribute (not value) and checked state is accessed via e.target.checked.

2. Multi-Input Form Code Example

import React, { useState } from 'react';

function FeedbackForm() {
  const [formData, setFormData] = useState({
    feedback: '',
    subscribe: false
  });

  const handleChange = (e) => {
    const { name, type, checked, value } = e.target;
    setFormData(prev => ({
      ...prev,
      [name]: type === 'checkbox' ? checked : value
    }));
  };

  return (
    <form onSubmit={e => e.preventDefault()}>
      <label>Your Comments:</label>
      <textarea
        name="feedback"
        value={formData.feedback}
        onChange={handleChange}
        rows="3"
      />

      <label style={{ display: 'flex', alignItems: 'center', gap: '8px', marginTop: '8px' }}>
        <input
          type="checkbox"
          name="subscribe"
          checked={formData.subscribe}
          onChange={handleChange}
        />
        Receive exam notifications by email
      </label>
    </form>
  );
}

Why is lifting state up required? Provide a real-time example.

Model Exam Answer

1. Why Lifting State Up is Required

Often, two or more sibling components need to share or react to the same changing data. In React's unidirectional data flow, sibling components cannot pass state directly sideways to each other. To keep data synchronized, developers lift state up to their closest common ancestor component.

2. Real-Time Example: Temperature Converter (Celsius & Fahrenheit)

import React, { useState } from 'react';

// Child Component: Reusable Temperature Input
function TemperatureInput({ scale, temperature, onTemperatureChange }) {
  return (
    <fieldset style={{ margin: '8px 0' }}>
      <legend>Enter temperature in {scale === 'c' ? 'Celsius' : 'Fahrenheit'}:</legend>
      <input
        value={temperature}
        onChange={e => onTemperatureChange(e.target.value)}
        type="number"
      />
    </fieldset>
  );
}

// Common Parent: Holds shared state and performs synchronization
function Calculator() {
  const [temperature, setTemperature] = useState('');
  const [scale, setScale] = useState('c');

  const handleCelsiusChange = (val) => {
    setScale('c');
    setTemperature(val);
  };

  const handleFahrenheitChange = (val) => {
    setScale('f');
    setTemperature(val);
  };

  const celsius = scale === 'f' && temperature !== ''
    ? ((parseFloat(temperature) - 32) * 5 / 9).toFixed(1)
    : temperature;
  const fahrenheit = scale === 'c' && temperature !== ''
    ? ((parseFloat(temperature) * 9 / 5) + 32).toFixed(1)
    : temperature;

  return (
    <div>
      <h3>Lifting State Up Calculator</h3>
      <TemperatureInput scale="c" temperature={celsius} onTemperatureChange={handleCelsiusChange} />
      <TemperatureInput scale="f" temperature={fahrenheit} onTemperatureChange={handleFahrenheitChange} />
    </div>
  );
}

Explain useState with an example of updating state objects and arrays.

Model Exam Answer

1. The useState Hook & Immutability

The useState hook lets functional components declare state variables. In React, state must be treated as immutable. Mutating an object or array in place (e.g. arr.push() or obj.name = 'X') does not change the object's reference memory address, causing React to miss the update and fail to re-render.

2. Correct Immutable Update Patterns

import React, { useState } from 'react';

function ProfileEditor() {
  // 1. Object State
  const [user, setUser] = useState({ name: 'Aki', sem: 5, college: 'MSRIT' });

  // 2. Array State
  const [courses, setCourses] = useState(['CN', 'ReactJS', 'AI']);

  // Updating Object: Use Object Spread (...)
  const updateCollege = () => {
    setUser(prev => ({
      ...prev,           // Copy existing properties
      college: 'Ramaiah Institute of Technology'
    }));
  };

  // Updating Array: Use Array Spread (...) or filter/map
  const addCourse = () => {
    setCourses(prev => [...prev, 'SE']); // Append without mutating original
  };

  const removeCourse = (courseToRemove) => {
    setCourses(prev => prev.filter(c => c !== courseToRemove)); // Return new array
  };

  return (
    <div>
      <h4>User: {user.name} ({user.college})</h4>
      <button onClick={updateCollege}>Update College</button>
      <h5>Courses:</h5>
      <ul>{courses.map(c => <li key={c}>{c}</li>)}</ul>
      <button onClick={addCourse}>Add SE</button>
    </div>
  );
}

Create a component that shows current time and updates every second using useEffect.

Model Exam Answer

1. Implementation Code: Live Clock with Interval Cleanup

import React, { useState, useEffect } from 'react';

function DigitalClock() {
  const [time, setTime] = useState(new Date().toLocaleTimeString());

  useEffect(() => {
    // Setup: start 1-second interval timer when component mounts
    const timerId = setInterval(() => {
      setTime(new Date().toLocaleTimeString());
    }, 1000);

    // Cleanup: clear timer when component unmounts to prevent memory leak
    return () => {
      clearInterval(timerId);
    };
  }, []); // Empty dependency array [] = run effect once on mount

  return (
    <div style={{
      display: 'inline-block',
      padding: '16px 24px',
      backgroundColor: '#0f172a',
      color: '#38bdf8',
      borderRadius: '8px',
      fontFamily: 'monospace',
      fontSize: '1.5rem',
      boxShadow: '0 4px 6px rgba(0,0,0,0.1)'
    }}>

      </div>

State the two Rules of Hooks in React and explain why these rules must be strictly followed.

Model Exam Answer

1. The Two Golden Rules of Hooks

  1. Only Call Hooks at the Top Level: Do not call hooks inside loops, conditions, or nested functions. Always use Hooks at the top level of your React function component before any early returns.
  2. Only Call Hooks from React Functions: Only call Hooks from React function components or from custom Hooks. Do not call Hooks from regular JavaScript functions.

2. Rationale: Hook Call Order Preservation

  • React does not rely on variable names to identify state. Instead, React maintains an internal linked-list / array of hook state cells for each component instance.
  • React relies on the exact order in which Hooks are called on every single render to match each Hook call with its corresponding internal state slot.
  • If a Hook is placed inside an if condition that evaluates to false on a subsequent render, the Hook call order is shifted, destroying state synchronization and causing runtime crashes.
Source: React Official Docs (Rules of Hooks); Unit 2 Slides (Unit-2.pdf, page 5)

What is Prop Drilling? How does the useContext hook solve this problem?

Model Exam Answer

1. Prop Drilling Problem

Prop drilling occurs when data must be passed from a high-level parent component to a deeply nested child component through multiple intermediate components that do not actually need the data themselves, acting solely as pass-through conduits.

2. Solution: React Context & useContext

Context provides a way to pass data through the component tree without having to pass props down manually at every level.

import React, { createContext, useContext, useState } from 'react';

// 1. Create Context
const ThemeContext = createContext('light');

// 2. Provider Component
function App() {
  const [theme, setTheme] = useState('dark');
  return (
    <ThemeContext.Provider value={theme}>
      <PageLayout /> {/* Intermediate component does not pass theme */}
    </ThemeContext.Provider>
  );
}

// 3. Deep Consumer Component
function ThemedButton() {
  // Access theme directly without prop drilling!
  const theme = useContext(ThemeContext);
  return <button className={`btn-${theme}`}>Current Theme: {theme}</button>;
}
