1. What is React? & Core Philosophy

Definition

React is an open-source, component-based JavaScript library created by Jordan Walke at Facebook (Meta) in 2013 for building rich, interactive, and high-performance user interfaces for Single Page Applications (SPAs).

1.1 The Three Pillars of React Philosophy

  1. 1. Declarative UI (Declarative vs. Imperative Programming):
    • Imperative (Traditional DOM/jQuery): You tell the browser step-by-step how to manipulate the DOM (e.g., document.getElementById('btn').classList.add('active')). This becomes notoriously bug-prone as application state grows complex.
    • Declarative (React): You declare what the UI should look like for a given state (e.g., <button className={isActive ? 'active' : ''}>). React automatically handles the underlying DOM mutations when state transitions.
  2. 2. Component-Based Architecture: UIs are constructed as independent, reusable, self-contained bricks called components. Each component encapsulates its own structure, internal state, and rendering logic.
  3. 3. One-Way (Unidirectional) Data Flow: Data strictly flows downward from parent components to child components via immutable props. This guarantees predictable state changes, eliminates cascading side-effects, and makes debugging straightforward.
Quick Recall

React is a declarative, component-driven UI library utilizing unidirectional data flow. You specify what the UI looks like for a state; React manages the DOM updates.

2. The Virtual DOM & Reconciliation

2.1 Why the Real Browser DOM is Slow

The native Browser Document Object Model (DOM) is a tree-like object structure representing HTML elements. Direct DOM manipulation is computationally expensive because altering a single node frequently forces the browser layout engine to trigger:

  • Reflow (Layout calculation): Recalculating the geometric coordinates and bounding boxes of all surrounding elements on the page.
  • Repaint: Redrawing pixels on screen to reflect style and geometry shifts.

2.2 What is the Virtual DOM?

The Virtual DOM (VDOM) is a lightweight, pure JavaScript object tree stored in memory that mirrors the actual DOM. It contains no browser-specific layout APIs, making in-memory operations instantaneous.

Figure 1.1: The Virtual DOM Diffing and Reconciliation Process
O(n)O(n)O(n) Heuristic Diff Computes Delta Patch Real Browser DOM Targeted Patch Minimal Reflow/Repaint
Reconciliation compares the new VDOM against the previous VDOM snapshot using an O(n)O(n)O(n) heuristic diff, applying only minimal batched patches to the real DOM.

2.3 The Reconciliation Algorithm & Fiber Architecture

A generic tree diffing algorithm operates in O(n3)O(n^3)O(n3) time complexity, which would be unusable for interfaces with thousands of elements. React achieves an optimal O(n)O(n)O(n) linear reconciliation via two core heuristics:

  1. Different Element Types: Two elements of different HTML types (e.g. changing <div> to <span>) will tear down and completely reconstruct that entire subtree from scratch.
  2. Keys for List Elements: Developers supply a persistent key prop so React can identify which items were inserted, deleted, or reordered without re-rendering the whole collection.
Quick Recall

VDOM is a lightweight in-memory JS representation of the UI. Reconciliation compares the new VDOM to the old VDOM via an O(n)O(n)O(n) heuristic diff and batches minimal updates to the real DOM.

4. Setting Up the React Environment with Vite

4.1 Why Vite Over Create React App (CRA)?

The legacy Create React App (CRA) utility relied on Webpack, which bundles the entire application codebase in memory before serving, leading to sluggish server start times and slow rebuilds as projects grew. Vite revolutionizes frontend tooling:

  • Instant Server Start: Leverages native browser ES Modules (ESM) to serve source code on-demand without bundling beforehand.
  • Lightning-Fast Pre-bundling: Uses esbuild (written in Go), pre-bundling dependencies 10−100×10-100\times10−100× faster than JavaScript-based bundlers.
  • Hot Module Replacement (HMR): Updates modified component files instantly in the browser without losing application state.

4.2 Bootstrapping a Modern Vite React Application

# 2. Navigate into the project folder
cd my-react-app

# 3. Install project dependencies
npm install

# 4. Launch the lightning-fast local development server
npm run dev
Quick Recall

Vite serves source code over native ES Modules (ESM) and uses Go-based esbuild for dependencies, offering near-instant dev server boot and fast Hot Module Replacement.

6. Introduction to JSX & Syntax Rules

Definition

JSX (JavaScript XML) is a syntax extension for JavaScript that allows developers to write HTML-like markup directly inside JavaScript files. It is not valid JavaScript natively; build tools transpile it into standard JavaScript function calls.

6.1 The Three Essential Rules of JSX

  1. 1. Return a Single Root Element: A component cannot return multiple adjacent top-level JSX tags. You must wrap them in a parent element or a React Fragment (<>...</> or <React.Fragment>), because JavaScript functions cannot return multiple values without an enclosing container.
  2. 2. Close All Tags: Every tag must be explicitly closed. Tags that are void in HTML (like <img>, <input>, <br>, <hr>) must be self-closing in JSX: <img src="..." alt="..." />.
  3. 3. camelCase Most HTML Attributes: Because JSX compiles to JavaScript objects and words like class and for are reserved keywords in JavaScript:
    • Use className instead of class.
    • Use htmlFor instead of for (in <label>).
    • Event handlers use camelCase: onClick, onChange, onSubmit.
    • Inline styles use camelCase properties inside double curly braces: style={{ backgroundColor: 'red', marginTop: '10px' }}.
Quick Recall

JSX rules: 1. Single root element (or Fragment <></>); 2. All tags must close (e.g. <br />); 3. camelCase attributes (className, htmlFor, onClick).

7. Embedding Expressions & Evaluation in JSX

You can embed any valid JavaScript expression inside JSX markup by enclosing it in curly braces { }:

jsx 
function UserGreeting() {
  const firstName = "Ananya";
  const unreadCount = 4;
  const user = { role: "admin", points: 150 };

  return (
    <div className="profile-banner">
      {/* 1. Variable interpolation */}
      <h1>Welcome back, {firstName}!</h1>

      {/* 2. Arithmetic expression */}
      <p>Bonus Points: {user.points * 2}</p>

      {/* 3. Function call evaluation */}
      <p>Role: {user.role.toUpperCase()}</p>

      {/* 4. Dynamic attribute value (notice no quotes around the braces!) */}
      <span title={`User has ${unreadCount} messages`}>
        Notifications: {unreadCount}
      </span>
    </div>
  );
}
Important Limitation

Only expressions (code that evaluates to a value) can be placed inside { }. JavaScript statements (like if (...), for (...), switch (...), or function (...) declarations) cannot be placed directly inside JSX curly braces!

Quick Recall

Curly braces { } open a window to JavaScript inside JSX. Only expressions (producing a value) are permitted; statements (if, for) cause syntax errors.

8. Conditional & List Rendering in JSX

8.1 Idiomatic Conditional Rendering Patterns

  • 1. Ternary Operator (condition ? <TrueView /> : <FalseView />): Used when you want to render one element when true, and an alternate element when false.
  • 2. Logical AND Short-Circuit (condition && <Component />): Used when you want to render a component only if a condition is true, and nothing if false.
    The "Zero" Pitfall

    Be careful when the condition is a number! In JavaScript, 0 && <Span /> evaluates to the number 0, which React renders as text "0" on screen. To prevent this, check boolean explicitly: messages.length > 0 && <Badge />.

  • 3. Early Return with if / else: When an entire component's return value depends on an early check (e.g. returning a loading spinner while data fetches).

8.2 Rendering Lists with the .map() Method and key Prop

In React, collections of data are transformed into arrays of JSX elements using standard JavaScript array .map():

jsx 
function CourseList() {
  const courses = [
    { id: "cs101", title: "ReactJS Fundamentals", credits: 1 },
    { id: "cs102", title: "Machine Learning", credits: 4 },
    { id: "cs103", title: "Computer Networks", credits: 4 }
  ];

  return (
    <ul className="course-list">
      {courses.map((course) => (
        // KEY PROP: Must be unique among siblings!
        <li key={course.id} className="course-item">
          <strong>{course.title}</strong> - {course.credits} Credits
        </li>
      ))}
    </ul>
  );
}
Why Array Indices Should Not Be Used as Keys

Using key={index} works for static, never-changing lists, but fails catastrophically if items can be sorted, filtered, inserted, or deleted. The index of an item changes when preceding items are modified, causing React to mistakenly match different component instances, resulting in corrupted form state and broken animations!

Quick Recall

Render lists using array.map(). Every item requires a unique, persistent key prop (use IDs, not indices) so the reconciliation algorithm can track element identity.

9. JSX Compilation Under the Hood

Browsers cannot execute JSX directly. Build tools like Babel or esbuild compile JSX into pure JavaScript before execution.

// StudentProfile.jsx
export default function StudentProfile() {
  const student = {
    name: "Aditya Kumar",
    usn: "1MS22IS045",
    gpa: 8.92,
    enrolledCourses: [
      { id: "is51", code: "IS51", name: "Machine Learning", credits: 4 },
      { id: "is53", code: "IS53", name: "Computer Networks", credits: 4 },
      { id: "isaec594", code: "ISAEC594", name: "ReactJS", credits: 1 }
    ],
    isEligibleForHonors: true
  };

  const totalCredits = student.enrolledCourses.reduce((sum, c) => sum + c.credits, 0);

  return (
    <div className="student-card" style={{ padding: "20px", border: "1px solid #ccc", borderRadius: "12px" }}>
      <h2>{student.name} <span style={{ fontSize: "14px", color: "#666" }}>({student.usn})</span></h2>
      <p>Current GPA: <strong>{student.gpa.toFixed(2)}</strong></p>
      
      {/* Conditional rendering using ternary operator */}
      <p>
        Academic Standing: {" "}
        {student.gpa >= 8.5 ? (
          <span style={{ color: "green", fontWeight: "bold" }}>Dean's Merit List 🌟</span>
        ) : (
          <span style={{ color: "blue" }}>Regular Standing</span>
        )}
      </p>

      {/* Logical AND short-circuit rendering */}
      {student.isEligibleForHonors && (
        <div className="honors-badge" style={{ backgroundColor: "#e6f4ea", padding: "8px", borderRadius: "6px" }}>
          ✅ Eligible for B.E. Honors Degree Specialization
        </div>
      )}

      <h3 style={{ marginTop: "16px" }}>Enrolled Courses ({totalCredits} Credits Total):</h3>
      <ul>
        {student.enrolledCourses.map((course) => (
          <li key={course.id}>
            <strong>{course.code}</strong> - {course.name} ({course.credits} cr)
          </li>
        ))}
      </ul>
    </div>
  );
}

2-Mark Conceptual Questions

📝 Practice Problem:
2 MARKS 1. What is the Virtual DOM and how does React reconciliation improve application performance?
Ans

Answer:

The Virtual DOM is a lightweight, tree-structured JavaScript object representation of the browser's actual DOM kept in memory.

  • When application state transitions occur, React re-renders the Virtual DOM tree in memory and compares it against the previous snapshot using an O(n)O(n)O(n) heuristic diffing algorithm called reconciliation.
  • Rather than causing expensive global page reflows and repaints in the browser, React calculates the minimal set of real DOM mutations required and applies them in a single optimized batch update.
📝 Practice Problem:
2 MARKS 2. State three fundamental syntax rules of JSX and explain why each is required.
Ans

Answer:

  1. Single Root Element: Every component must return exactly one parent root element or a Fragment (<>...</>). Reason: JSX compiles to a single function call (React.createElement(...)), which can only return a single JavaScript value.
  2. Explicit Closing of All Tags: All tags must be explicitly closed, including void/self-closing elements (e.g. <img />, <input />, <br />). Reason: JSX follows XML/XHTML well-formed syntax strictly.
  3. camelCase Attribute Naming: HTML attributes must be written in camelCase (e.g. className instead of class, htmlFor instead of for, tabIndex). Reason: class and for are reserved keywords in JavaScript.
📝 Practice Problem:
2 MARKS 3. Why should array indices not be used as the 'key' prop when rendering dynamic lists in React?
Ans

Answer:

Using array index (e.g., key={index}) ties element identity to its sequential array position rather than its actual data identity.

  • If items in the list are reordered, inserted at the beginning, or filtered out, their numerical index changes.
  • React's reconciliation algorithm assumes the item at index 0 is the same node across renders, causing severe bugs such as uncontrolled component state retention (e.g., text remaining in swapped input fields), broken transitions, and performance degradation. Unique, persistent entity IDs (e.g., key={item.id}) must always be used.
📝 Practice Problem:
2 MARKS 4. Distinguish between JavaScript expressions and statements in JSX. Give an example of an invalid JSX embedding.
Ans

Answer:

  • Expressions: Code constructs that evaluate to a single value (e.g., variable references, ternaries a ? b : c, function calls, arithmetic). Expressions can be embedded inside curly braces {expression} in JSX.
  • Statements: Code constructs that perform an action or control flow but do not evaluate directly to a value (e.g., if (...), for (...), while (...), switch).
  • Invalid JSX Example: <div>{if (user.active) { "Active" }}</div> results in a JavaScript syntax error because an if statement cannot be passed as an argument to React.createElement(). The valid alternative is ternary: <div>{user.active ? "Active" : "Inactive"}</div>.
📝 Practice Problem:
2 MARKS 5. What is meant by unidirectional (one-way) data flow, and why is it beneficial?
Ans

Answer:

In React, data strictly flows in one direction: from parent components down to child components via immutable props. Child components cannot directly modify the props they receive; they can only notify parents by invoking callback functions passed down as props.

Benefits: Eliminates hidden side-effects, guarantees deterministic application state, simplifies debugging through predictable top-down data cascades, and prevents cyclical state dependency cascades.

📝 Practice Problem:
5 MARKS 7. Explain the reconciliation algorithm in React. How does React achieve O(n)O(n)O(n) time complexity?
Ans

Answer:

Theoretical minimum algorithms for comparing two arbitrary trees require O(n3)O(n^3)O(n3) operations (where nnn is the total count of tree nodes). In a web application with 1,000 DOM nodes, an O(n3)O(n^3)O(n3) algorithm would require one billion comparisons per render cycle, completely stalling the browser thread.

React implements an O(n)O(n)O(n) heuristic diffing algorithm based on two fundamental assumptions:

  1. Elements of Different Types Produce Different Trees: Whenever the root element type changes (e.g. from <div> to <span>, or <Header> to <Nav>), React unmounts the entire old subtree and recreates the new DOM subtree from scratch without inspecting deeper children.
  2. Keys Identify Stable Children Across Renders: For children lists, React uses the unique key prop to match children in the original tree with children in the subsequent tree. This allows React to detect insertions, deletions, and moves in linear O(n)O(n)O(n) time rather than checking all permutations.
📝 Practice Problem:
5 MARKS 8. Explain why modern React development replaced Create React App (CRA) with Vite. Contrast their architectural approaches.
Ans

Answer:

  • Create React App (CRA / Webpack Architecture): CRA relies on Webpack, which bundles the entire application source code and all node_modules into monolithic bundles before starting the development server. As the codebase expands to hundreds of modules, server startup takes 30-90 seconds, and Hot Module Replacement (HMR) experiences perceptible multi-second lag.
  • Vite Architecture (Native ESM + esbuild):
    • Instant Dev Server Startup: Vite serves source code over native browser ES Modules (import / export). The browser requests modules on-demand as they are needed, eliminating bundle wait time.
    • Fast Dependency Pre-bundling: Dependencies written in CommonJS or UMD are pre-bundled using esbuild (written in Go), which executes 10× to 100× faster than JS-based bundlers.
    • Instant Hot Module Replacement (HMR): When a file is edited, Vite invalidates and re-transpiles only that specific module over native ESM, keeping HMR speed constant regardless of total project size.

PRACTICE 4 • FALSY VALUE SHORT-CIRCUIT TRAP

What gets rendered in the browser DOM for <div>{unreadCount && <span>New Items</span>}</div> when unreadCount = 0? Explain why this happens and provide the fix.

📝 Practice Problem:
Show Step-by-Step Solution
Ans

Unexpected Output: The browser renders <div>0</div>!

Explanation: In JavaScript, the short-circuit operator && evaluates the left-hand side. If it is falsy, it returns that falsy value immediately. Since 0 is falsy, the expression evaluates to the number 0. While React does not render false, null, or undefined, it does render numbers, so the digit 0 is injected directly into the DOM.

Recommended Fix: Coerce to boolean or compare explicitly:

{unreadCount > 0 && New Items}

{/* Fix 2: Boolean conversion */}
{Boolean(unreadCount) && New Items}
