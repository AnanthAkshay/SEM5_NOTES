§ 1

Data Link Layer Duties & Framing Methods

The Data Link Layer (DLL) transforms a raw, error-prone transmission facility into a reliable, hop-to-hop link for the Network Layer. It accomplishes this by packaging network-layer packets into discrete units called frames, regulating transmission speed via flow control, and detecting physical errors.

CORE RESPONSIBILITIES OF THE DATA LINK LAYER
  • Framing: Divides the stream of bits received from the physical layer into manageable data units (frames) with distinct header and trailer delimiters.
  • Physical Addressing: Appends a header containing the physical hardware addresses (48-bit MAC addresses) of the sender and immediate receiver.
  • Flow Control: Prevents a fast sender from swamping a slow receiver using feedback-based sliding window mechanisms.
  • Error Control: Detects and retransmits damaged or lost frames by adding trailers containing Cyclic Redundancy Check (CRC) codes.
  • Access Control: In broadcast channels, determines which device has permission to transmit at any given time (MAC sublayer).

Framing Techniques: Character Count vs Stuffing

Framing Technique Delimiter / Mechanism Operation & Vulnerability
Character Count Integer in the frame header specifies total frame length. Fatal flaw: If the count field is corrupted by a single bit flip, the receiver loses frame synchronization for all subsequent frames. Deprecated in modern networks.
Byte Stuffing (Byte-Oriented) Special flag bytes (e.g. `FLAG = 0x7E`) delimit start and end of frames. If the flag pattern occurs naturally within data, the sender inserts an escape byte (`ESC = 0x7D`) before it. If an `ESC` occurs in data, it is escaped with another `ESC` (`ESC ESC`). Receiver strips the stuffing `ESC`.
Bit Stuffing (Bit-Oriented) Special bit pattern `01111110` (six consecutive 1s) delimits frame boundaries. Rule: Whenever the sender encounters five consecutive 1s (`11111`) in user data, it automatically stuffs a `0` after the fifth 1. Receiver detects five 1s and discards the stuffed 0.
WORKED EXAMPLE: BIT STUFFING & UNSTUFFING

Input Bit Stream: 010011111011111101011111110

Step 1: Sender Stuffing (Insert 0 after every five consecutive 1s):

  • 0100 11111 → stuff 0 → 0100 11111[0] 0
  • 111111 → after five 1s, stuff 0 → 11111[0] 10
  • 010 11111110 → after five 1s, stuff 0 → 010 11111[0] 110

Stuffed Stream Transmitted: 0100111110011111010010111110110

Step 2: Receiver Unstuffing: Receiver encounters five 1s followed by a 0, removes the 0, perfectly restoring the original data stream.

QUICK RECALL
  • DLL handles hop-to-hop delivery using 48-bit physical MAC addresses.
  • Byte stuffing escapes special flag bytes with `ESC`.
  • Bit stuffing inserts a `0` after every five consecutive 1s (`11111`) to prevent imitation of flag `01111110`.
§ 2

Address Resolution Protocol (ARP)

While the Network Layer routes packets based on 32-bit logical IPv4 addresses, physical local area networks (such as Ethernet) only deliver frames using 48-bit physical MAC addresses. The Address Resolution Protocol (ARP) dynamically maps a known IP address to its unknown physical MAC address on the local link.

ARP Protocol Exchange: Broadcast Request & Unicast Reply

ARP Packet Fields (28-Byte Payload)

Field Name Length Description
Hardware Type (HTYPE) 16 bits Physical network protocol (Ethernet = `1`).
Protocol Type (PTYPE) 16 bits Network layer protocol (IPv4 = `0x0800`).
Hardware Length (HLEN) 8 bits Length of hardware address in bytes (Ethernet = `6`).
Protocol Length (PLEN) 8 bits Length of logical address in bytes (IPv4 = `4`).
Operation Code (OPER) 16 bits `1` for ARP Request, `2` for ARP Reply.
Sender Hardware / IP 6 + 4 bytes MAC address and IP address of the transmitting node.
Target Hardware / IP 6 + 4 bytes Target MAC (`00:00:00:00:00:00` in request) and Target IP.
SECURITY WARNING: ARP SPOOFING / POISONING

Because ARP is completely stateless and does not authenticate replies, an attacker on the same local subnet can send unsolicited (gratuitous) fake ARP replies claiming their MAC address belongs to the default gateway's IP. All outbound traffic from victim hosts is then silently routed through the attacker (Man-in-the-Middle attack).

QUICK RECALL
  • ARP maps 32-bit IPv4 address → 48-bit MAC address.
  • ARP Request is a Broadcast (`FF:FF:FF:FF:FF:FF`); ARP Reply is a Unicast.
  • ARP Cache stores mappings temporarily with a Time-to-Live (TTL).
§ 3

Error Detection, Correction & Block Coding

Electromagnetic noise and interference inevitably introduce errors during physical transmission. Errors are classified as single-bit errors (only 1 bit inverted in the entire data unit) or burst errors (2 or more consecutive bits corrupted, where the burst length is measured from the first to the last corrupted bit).

Hamming Distance

HAMMING DISTANCE DEFINITION

The Hamming distance $d(x, y)$ between two binary words of equal length is the number of bit positions in which the corresponding bits differ. It is easily calculated by taking the bitwise exclusive-OR ($x \oplus y$) and counting the number of 1s (Hamming weight).

Example: $x = 10101$ and $y = 11110$. $x \oplus y = 01011$ (three 1s) &implies; $d(x, y) = 3$.

The minimum Hamming distance $d_{min}$ of a code is the smallest Hamming distance between all distinct pairs of valid codewords in that code.

Mathematical Criteria for Detection and Correction

HAMMING DISTANCE CRITERIA
  1. To detect up to $s$ errors: $$\mathbf{d_{min} \ge s + 1}$$ Intuition: If a transmitted codeword incurs up to $s$ bit flips, the received pattern will lie at a distance $\le s$ from the original codeword, but at least 1 flip away from any other valid codeword, guaranteeing detection.
  2. To correct up to $t$ errors: $$\mathbf{d_{min} \ge 2t + 1}$$ Intuition: Spheres of radius $t$ drawn around valid codewords must never intersect. A received word with up to $t$ errors is uniquely closer to the original transmitted codeword than to any other.
QUICK RECALL
  • Hamming distance $d(x, y)$ = number of differing bits = weight of $x \oplus y$.
  • Error Detection: $d_{min} \ge s + 1$. Example: to detect 2 errors, $d_{min} \ge 3$.
  • Error Correction: $d_{min} \ge 2t + 1$. Example: to correct 1 error, $d_{min} \ge 3$.
§ 4

Cyclic Redundancy Check (CRC)

Cyclic Redundancy Check (CRC) is an exceptionally powerful, hardware-friendly error-detecting code used across Ethernet, Wi-Fi, and storage systems. It treats binary bit streams as algebraic polynomials with binary coefficients and performs modulo-2 polynomial division.

CRC SENDER AND RECEIVER ALGORITHM

Let dataword $D$ have $k$ bits, and generator polynomial $G(x)$ have degree $r$ ($r + 1$ bits):

  1. Sender Step 1: Append $r$ zeros to the right of dataword $D$, forming $D \cdot 2^r$.
  2. Sender Step 2: Divide the appended bit stream $D \cdot 2^r$ by the divisor $G(x)$ using modulo-2 binary division (bitwise XOR subtraction, no carries or borrows).
  3. Sender Step 3: The division yields a quotient (discarded) and an $r$-bit remainder $R$, called the CRC.
  4. Sender Step 4: Append the $r$-bit CRC remainder to original dataword $D$. Transmit codeword $T = D \cdot 2^r \oplus R$.
  5. Receiver Step: Divide the received codeword $T'$ by the identical generator $G(x)$. If the remainder is strictly all zeros, accept the frame; otherwise, an error occurred — discard frame!

§ 5

The Internet Checksum Algorithm

The Internet Checksum is utilized by IP, TCP, and UDP. It treats data as a sequence of 16-bit integers and computes their sum using one's complement arithmetic with end-around carry.

CHECKSUM COMPUTATION STEPS

At Sender:

  1. Divide data into 16-bit words. (If length is odd, pad with a trailing zero byte).
  2. Sum all 16-bit words together.
  3. If a carry bit overflows beyond 16 bits (bit 16), wrap the carry around and add it to the least significant bit (LSB). Repeat until no carry remains.
  4. Take the bitwise NOT (one's complement) of the 16-bit sum. This is the Checksum.
  5. Send the data words along with the checksum.

At Receiver: Sum all received 16-bit words including the checksum using one's complement. If the result is all 1s (`0xFFFF`), which when complemented yields `0x0000`, the packet is accepted!

Compute 16-bit Internet Checksum for Given Words

Calculate the Internet Checksum for the following three 16-bit hexadecimal words:

$$\text{Word 1: } \text{0x4500}, \quad \text{Word 2: } \text{0x003C}, \quad \text{Word 3: } \text{0x1C46}$$

Step 1: Standard Binary/Hexadecimal Addition:

$$\begin{aligned} &\text{0x4500} \\ + &\text{0x003C} = \text{0x453C} \\ + &\text{0x1C46} = \text{0x6182} \end{aligned}$$

Since the sum $\text{0x6182}$ fits in 16 bits without carry overflow, wrapped sum $= \text{0x6182}$.

Step 2: Take One's Complement (Bitwise Inversion):

$$\text{Sum} = 0110\ 0001\ 1000\ 0010_2\ (\text{0x6182})$$ $$\text{Checksum} = \sim \text{Sum} = 1001\ 1110\ 0111\ 1101_2 = \mathbf{\text{0x9E7D}}$$

Step 3: Receiver Verification:

$$\text{0x4500} + \text{0x003C} + \text{0x1C46} + \text{0x9E7D} = \text{0x6182} + \text{0x9E7D} = \mathbf{\text{0xFFFF}}$$
Inverting $\text{0xFFFF}$ gives $\mathbf{\text{0x0000}}$. The data is completely verified!
QUICK RECALL
  • Internet Checksum uses 16-bit one's complement addition with end-around carry.
  • Sender checksum = bitwise NOT of sum.
  • Receiver sum of all words + checksum must equal all 1s (`0xFFFF`).
§ 6

Random Access Protocols: ALOHA & CSMA/CD

In a broadcast network, multiple stations share a single communication channel. Random Access (Contention) Protocols allow stations to transmit whenever they have data, resolving collisions when simultaneous transmissions overlap.

1. Pure ALOHA vs Slotted ALOHA Throughput Analysis

Let $G$ be the offered load (average number of frame generation requests per frame transmission time $T_{fr}$):

Protocol Vulnerable Window Throughput Formula Max Load ($G^*$) Max Throughput ($S_{max}$)
Pure ALOHA $$2 \times T_{fr}$$ $$S = G e^{-2G}$$ $$G = 0.5$$ $$\frac{1}{2e} \approx \mathbf{18.4\%}$$
Slotted ALOHA $$T_{fr}$$ $$S = G e^{-G}$$ $$G = 1.0$$ $$\frac{1}{e} \approx \mathbf{36.8\%}$$

2. Carrier Sense Multiple Access (CSMA)

Before transmitting, stations "listen before speaking" (sense the carrier) to avoid obvious collisions:

  • 1-Persistent CSMA: If channel is idle, transmit immediately. If busy, continue sensing continuously until idle, then transmit with probability $p=1$. (High collision probability when two waiting stations transmit simultaneously upon channel becoming idle).
  • Non-Persistent CSMA: If idle, transmit immediately. If busy, wait a random backoff time before sensing again. (Reduces collisions, but introduces channel idle time).
  • p-Persistent CSMA: Used in slotted channels. If idle, transmit with probability $p$; defer to next slot with probability $1 - p$.

3. CSMA with Collision Detection (CSMA/CD)

Stations "listen while talking". If two signals collide on the wire, the collision energy spike is detected immediately, transmission is aborted, a 32-bit jamming signal is broadcast to alert all nodes, and stations invoke the Binary Exponential Backoff algorithm.

CSMA/CD MINIMUM FRAME LENGTH RULE

For a station to reliably detect a collision before it finishes transmitting its frame, the frame transmission time $T_{fr}$ must be at least twice the maximum end-to-end propagation delay $t_{prop}$ (round-trip time):

$$T_{fr} \ge 2 \times t_{prop}$$

Since $T_{fr} = \frac{L_{min}}{\text{Bandwidth}}$, we have the fundamental dimensioning formula:

$$\mathbf{L_{min} \ge 2 \times t_{prop} \times \text{Bandwidth}}$$

CSMA/CD Minimum Frame Size Calculation

A network operating CSMA/CD has a transmission bandwidth of $R = 10\text{ Mbps}$, a maximum cable length of $d = 2500\text{ m}$, and a signal propagation velocity of $v = 2 \times 10^8\text{ m/s}$. Calculate the minimum frame size required for collision detection.

Step 1: Calculate One-Way Propagation Delay ($t_{prop}$):

$$t_{prop} = \frac{d}{v} = \frac{2500\text{ m}}{2 \times 10^8\text{ m/s}} = 1.25 \times 10^{-5}\text{ s} = 12.5\text{ }\mu\text{s}$$

Step 2: Calculate Round-Trip Time ($RTT = 2 t_{prop}$):

$$RTT = 2 \times t_{prop} = 2 \times 12.5\text{ }\mu\text{s} = 25.0\text{ }\mu\text{s}$$

Step 3: Apply Minimum Frame Size Equation:

$$L_{min} = 2 \times t_{prop} \times R = (25.0 \times 10^{-6}\text{ s}) \times (10 \times 10^6\text{ bps}) = \mathbf{250\text{ bits}}$$
$$L_{min} = \frac{250}{8} = \mathbf{31.25\text{ bytes}} \approx \mathbf{32\text{ bytes}}$$

Standard Ethernet Note: In IEEE 802.3 10BASE5 standard Ethernet, accounting for 4 repeaters and worst-case delay, round-trip time is standardized to $51.2\text{ }\mu\text{s}$, producing the famous minimum frame size of $\mathbf{512\text{ bits} = 64\text{ bytes}}$.

QUICK RECALL
  • Pure ALOHA max throughput: $18.4\%$ at $G = 0.5$. Slotted ALOHA max throughput: $36.8\%$ at $G = 1.0$.
  • CSMA: 1-persistent (greedy), non-persistent (random wait), p-persistent (probabilistic).
  • CSMA/CD requires $T_{fr} \ge 2 t_{prop} \implies L_{min} \ge 2 t_{prop} \times \text{Bandwidth}$.
§ 7

Controlled Access & Channelization Protocols

Unlike random access where stations compete and collide, Controlled Access ensures collision-free communication by having stations consult each other before transmitting, while Channelization divides channel capacity across frequency, time, or orthogonal code space.

1. Controlled Access Protocols

Protocol Operational Mechanism Pros & Cons
Reservation Time is divided into intervals. In each interval, a reservation frame precedes data frames. Stations declare their intent in small mini-slots before sending. Collision-free; overhead of reservation mini-slots.
Polling One device acts as Primary (controller); others are Secondaries. Primary queries secondaries via Poll (to receive data) or Select (to send data). Centralized control; single point of failure at primary; polling overhead latency.
Token Passing Stations organized in a logical ring. A special bit pattern called the Token circulates. A station holding the token has exclusive right to transmit. Deterministic, fair under heavy loads; token maintenance overhead (lost token, duplicate token).

2. Channelization Protocols (FDMA, TDMA, CDMA)

  • FDMA (Frequency-Division Multiple Access): Available channel bandwidth is partitioned into discrete frequency bands separated by guard bands. Each station transmits continuously on its assigned band.
  • TDMA (Time-Division Multiple Access): Stations share the entire frequency bandwidth but are allocated synchronized time slots within periodic frames.
  • CDMA (Code-Division Multiple Access): All stations transmit simultaneously over the entire frequency bandwidth! Signals are separated by assigning each station an orthogonal chipping code (Walsh sequence) where: $$\mathbf{c_i \cdot c_j = 0 \quad (i \ne j)}, \quad \mathbf{c_i \cdot c_i = m}$$
QUICK RECALL
  • Controlled access: Reservation (mini-slots), Polling (Primary/Secondary), Token Passing (Token Ring).
  • FDMA separates by frequency bands; TDMA separates by synchronized time slots.
  • CDMA allows simultaneous transmission over full bandwidth using orthogonal Walsh codes.

Important Examination Questions

2-Mark Questions (Short Answer)

2M What is the purpose of bit stuffing in framing?

Answer: Bit stuffing prevents user data patterns from being falsely interpreted as frame boundary delimiters. Whenever the sender detects five consecutive 1s (`11111`) in data, it stuffs a `0`, preventing the flag sequence `01111110` from appearing in the payload.

2M State the condition on minimum Hamming distance to correct $t$ errors.

Answer: $d_{min} \ge 2t + 1$. This guarantees that spheres of radius $t$ centered around valid codewords never overlap, allowing unique nearest-neighbor correction.

2M Compare maximum throughput of Pure ALOHA and Slotted ALOHA.

Answer: Pure ALOHA has a maximum throughput of $18.4\%$ ($1/2e$) at an offered load of $G = 0.5$, whereas Slotted ALOHA doubles maximum throughput to $36.8\%$ ($1/e$) at $G = 1.0$ by eliminating partial frame overlaps.

5-Mark Questions (Medium Length)

5M Explain the working of the Address Resolution Protocol (ARP).

Answer: When a source host needs to send an IP datagram to a local target but only knows the target's IP address, it broadcasts an ARP Request packet (`FF:FF:FF:FF:FF:FF`) asking "Who has IP X? Tell IP Y". Every host on the subnet receives the broadcast, but only the machine with IP X replies with an ARP Reply packet sent unicast back to the source containing its 48-bit physical MAC address. The source updates its ARP cache with a TTL.

5M Explain why CSMA/CD imposes a restriction on minimum frame size.

Answer: In CSMA/CD, a station must detect a collision before it finishes transmitting its frame so it knows whether retransmission is needed. In the worst case, a collision occurs just before the signal reaches the furthest station at time $t_{prop}$, and the collision signal takes another $t_{prop}$ to propagate back. Therefore, the transmission duration must satisfy $T_{fr} \ge 2 t_{prop}$, yielding $L_{min} \ge 2 t_{prop} \times \text{Bandwidth}$.

PRACTICE 1 • HAMMING DISTANCE

A code has a minimum Hamming distance of $d_{min} = 5$. How many errors can it detect, and how many can it correct?

Show Step-by-Step Solution
  • Error detection: $d_{min} \ge s + 1 \implies 5 \ge s + 1 \implies s = \mathbf{4\text{ errors detected}}$.
  • Error correction: $d_{min} \ge 2t + 1 \implies 5 \ge 2t + 1 \implies 2t \le 4 \implies t = \mathbf{2\text{ errors corrected}}$.
PRACTICE 2 • ALOHA THROUGHPUT

In Pure ALOHA, if the offered load is $G = 1$, what is the throughput $S$?

Show Step-by-Step Solution

Formula: $S = G e^{-2G}$

$$S = 1 \times e^{-2(1)} = e^{-2} \approx \frac{1}{7.389} \approx \mathbf{0.1353\ (13.53\%)}$$

Notice that at $G=1$, Pure ALOHA throughput degrades to $13.53\%$ due to high collision frequency, well below its peak of $18.4\%$ at $G=0.5$.
