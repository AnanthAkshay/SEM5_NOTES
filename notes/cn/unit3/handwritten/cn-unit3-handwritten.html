Network Layer Services & Switching Models

§ 1

The Network Layer is responsible for host-to-host delivery of individual packets across multiple diverse network links. It encapsulates transport-layer segments into network datagrams at the sender, routes them across intermediate routers, and delivers them to the destination host.

THREE FUNDAMENTAL NETWORK LAYER SERVICES:
  1. Packetizing: Encapsulating the transport-layer payload into a network-layer datagram by adding an IP header at the source, and decapsulating it at the destination.
  2. Routing: The global decision-making process of determining the optimal, end-to-end path that packets should traverse from source to destination using routing protocols (OSPF, BGP, RIP).
  3. Forwarding: The local action taken by each individual router of transferring a packet from an incoming interface link to the appropriate outgoing interface link based on its forwarding table.

Datagram (Connectionless) vs Virtual-Circuit (Connection-Oriented) Networks

Feature / Dimension Datagram Approach (e.g. The Internet / IP) Virtual-Circuit Approach (e.g. ATM, X.25)
Setup Phase None. Packets can be injected immediately. Mandatory connection setup phase before sending data; teardown after.
Packet Header Contains full 32-bit (or 128-bit) Source and Destination IP addresses. Contains only a short Virtual Circuit Identifier (VCI) label.
Routing Path Each datagram is routed independently. Packets between same source and destination may take completely different paths. All packets for a connection follow the exact same established physical path.

Network Performance & Delay Modeling

§ 2

As a datagram journeys from source host to destination, it encounters four distinct delay components at every intermediate router. Understanding these delays is essential for network dimensioning and quality of service (QoS).

TOTAL NODAL DELAY EQUATION:
dnodal=dproc+dqueue+dtrans+dprop\mathbf{d_{nodal} = d_{proc} + d_{queue} + d_{trans} + d_{prop}}dnodal​=dproc​+dqueue​+dtrans​+dprop​
  1. Processing Delay (dprocd_{proc}dproc​): The time required for a router to inspect the packet header, check bit-level checksums, and look up the destination IP in the routing table (microseconds).
  2. Queuing Delay (dqueued_{queue}dqueue​): The time a packet spends waiting in the router's transmission buffer queue before being placed on the link. Highly variable, depends on traffic congestion and queue depth.
  3. Transmission Delay (dtransd_{trans}dtrans​): The time required to push all bits of the packet onto the physical transmission link: dtrans=LR[seconds]d_{trans} = \frac{L}{R} \quad \text{[seconds]}dtrans​=RL​[seconds] where LLL is packet length (bits) and RRR is link transmission rate / bandwidth (bps).
  4. Propagation Delay (dpropd_{prop}dprop​): The time required for a single bit to travel physically across the transmission medium from source to destination: dprop=dv[seconds]d_{prop} = \frac{d}{v} \quad \text{[seconds]}dprop​=vd​[seconds] where ddd is distance (meters) and vvv is propagation velocity of the medium (≈2×108 m/s\approx 2 \times 10^8\text{ m/s}≈2×108 m/s in copper/fiber, 3×108 m/s3 \times 10^8\text{ m/s}3×108 m/s in air).
CRITICAL DISTINCTION: TRANSMISSION VS PROPAGATION DELAY:

Transmission delay (L/RL/RL/R) depends on packet size and transmission rate (bandwidth). It is the time to push the bits into the pipe.

Propagation delay (d/vd/vd/v) depends solely on physical distance and propagation velocity. It is the time for a bit to travel through the pipe.

Bandwidth-Delay Product (BDP)

The Bandwidth-Delay Product defines the volume of bits that can fill the transmission link end-to-end at any instant (the "pipe volume"):

BDP=Bandwidth×Delay=R×tprop\mathbf{\text{BDP} = \text{Bandwidth} \times \text{Delay} = R \times t_{prop}}BDP=Bandwidth×Delay=R×tprop​

2. Classless Inter-Domain Routing (CIDR)

Classful addressing caused massive address wastage (a company needing 500 hosts had to take a Class B with 65,534 addresses). In 1993, CIDR (Classless Inter-Domain Routing) abandoned fixed classes in favor of arbitrary prefix lengths specified using slash notation (`/n`).

The IPv4 Datagram Header & Fragmentation

§ 5

The IPv4 Datagram Header is a 20-to-60 byte protocol control structure prefixing every Internet packet. Because underlying physical networks possess different Maximum Transmission Units (MTUs), the network layer must fragment oversized datagrams and reassemble them at the final destination host.

Structure of the IPv4 Datagram Header (32 Bits Wide)

Key Header Fields & Explanations

  • VER (4 bits): IP version number (always `4` for IPv4).
  • IHL (4 bits): Internet Header Length in 4-byte (32-bit) words. Minimum is 5×4=20 bytes5 \times 4 = 20\text{ bytes}5×4=20 bytes; maximum is 15×4=60 bytes15 \times 4 = 60\text{ bytes}15×4=60 bytes.
  • Total Length (16 bits): Total datagram length (header + payload) in bytes. Maximum theoretical size is 216−1=65,535 bytes2^{16} - 1 = 65,535\text{ bytes}216−1=65,535 bytes.
  • Time to Live (TTL, 8 bits): Hop limit counter. Decremented by 1 at every router hop. When TTL reaches 0, the datagram is dropped and an ICMP Time Exceeded message is sent back to the source (prevents infinite routing loops).
  • Protocol (8 bits): Identifies the transport-layer protocol carried in payload: `1` for ICMP, `6` for TCP, `17` for UDP.
  • Flags (3 bits): Bit 0: Reserved (0). Bit 1: DF (Don't Fragment): if 1, router cannot fragment packet; if oversized, router drops it. Bit 2: MF (More Fragments): 1 means more fragments follow; 0 means this is the final fragment.
  • Fragment Offset (13 bits): Relative position of the fragmented data payload compared to the original unfragmented payload, measured in 8-byte (64-bit) units.

Internet Control Message Protocol (ICMPv4)

§ 6

IPv4 is a best-effort, connectionless datagram protocol lacking built-in error reporting or query management. ICMPv4 operates as an companion protocol at the Network Layer to report transmission errors back to the source and provide diagnostic queries.

RULES FOR SUPPRESSING ICMP ERROR GENERATION:

To avoid broadcast storms and infinite message loops, ICMP error messages are NEVER generated in response to:

  • Another ICMP error message (no error about an error!).
  • A datagram carrying a broadcast or multicast destination address.
  • Any datagram fragment other than the initial fragment (offset 0).
QUICK RECALL
  • ICMP runs over IP (Protocol number = 1).
  • `ping` uses Type 8 (Echo Request) & Type 0 (Echo Reply).
  • `traceroute` uses Type 11 (Time Exceeded, TTL=0).
  • Never generate an ICMP error in response to an ICMP error or broadcast packet!

Routing Algorithms: Distance Vector & Dijkstra's Link State

§ 7

A routing algorithm determines the optimal (least-cost) path through the network graph. The two foundational dynamic routing paradigms are Distance Vector Routing (Bellman-Ford) and Link State Routing (Dijkstra).

1. Distance Vector Routing (Bellman-Ford Algorithm)

In Distance Vector (e.g. RIP), each router maintains a table containing its estimated distance to every destination in the network. Periodically and asynchronously, each router transmits its entire distance vector only to its immediate neighbors.

BELLMAN-FORD OPTIMALITY EQUATION:
Dx(y)=min⁡v{c(x,v)+Dv(y)}D_x(y) = \min_v \left\{ c(x, v) + D_v(y) \right\}Dx​(y)=vmin​{c(x,v)+Dv​(y)}

Where c(x,v)c(x, v)c(x,v) is the cost of the direct link from router xxx to neighbor vvv, and Dv(y)D_v(y)Dv​(y) is neighbor vvv's advertised cost to reach destination yyy.

COUNT-TO-INFINITY PROBLEM & REMEDIES:

Distance Vector algorithms suffer from slow convergence when links fail: "Good news travels fast, bad news travels slow." Two adjacent routers can create a routing loop by continually incrementing their path estimates through each other towards infinity.

Remedies:

  • Split Horizon: Do not advertise a route back out the same interface through which it was learned.
  • Poison Reverse: Advertise the route back to that neighbor with a cost of ∞\infty∞ (unreachable).
  • Hold-down Timers: Ignore route updates for a failed link for a defined period while network converges.

2. Link State Routing (Dijkstra's Algorithm)

In Link State Routing (e.g. OSPF), every router discovers its neighbors and link costs, builds a Link State Advertisement (LSA), and floods it to every router in the entire network. Every router constructs an identical, complete map of the network topology graph and independently runs Dijkstra's Shortest Path First (SPF) algorithm.

Solution:

Answer: Routing is the global process of determining the end-to-end optimal path across the entire network (control plane). Forwarding is the local operation at a router transferring a packet from its input link to the appropriate output link based on its forwarding table (data plane).

📝 Practice Problem:
2M What is the purpose of the TTL field in the IPv4 header?
Solution:

Answer: Time-to-Live (TTL) prevents packets from circulating endlessly in routing loops. It is decremented by 1 at every router hop; when it reaches 0, the packet is discarded and an ICMP Time Exceeded message is returned to the source.

5-Mark Questions (Medium Length)

📝 Practice Problem:
5M Compare Distance Vector Routing with Link State Routing.
Solution:

Answer:

  • Information shared: Distance Vector shares its entire distance table only with immediate neighbors. Link State shares only link states to its immediate neighbors, but floods this to all routers in the entire network.
  • Convergence: Distance Vector converges slowly and suffers from count-to-infinity loops. Link State converges rapidly without loops.
  • Computational complexity: Distance Vector runs localized Bellman-Ford calculations. Link State requires every router to independently execute Dijkstra's algorithm (O(∣V∣2)O(|V|^2)O(∣V∣2)).
📝 Practice Problem:
5M Explain Network Address Translation (NAT) and its advantages.
Solution:

Answer: NAT maps multiple private IPv4 addresses from internal networks (RFC 1918) to a single registered public IP address when communicating over the Internet. It conserves globally routable IPv4 addresses and enhances security by masking internal network topologies from outside observation.

Ramaiah Internal Assessment - II (2025) • Q 3(b) [10 Marks • Blooms L2, CO3]

"Discuss the transition mechanisms from IPv4 to IPv6: Dual Stack, Tunneling, and Header Translation."

Because the global Internet cannot be upgraded from IPv4 to IPv6 overnight, the IETF standardized three fundamental co-existence strategies:

  1. 1. Dual Stack (RFC 4213):
    • Hosts and routers run both IPv4 and IPv6 protocol stacks simultaneously on the same physical interfaces.
    • When an application initiates communication, DNS queries return both an A record (IPv4) and an AAAA record (IPv6). If IPv6 is available, the client prioritizes the IPv6 stack; otherwise, it falls back seamlessly to IPv4.
    • Advantage: Cleanest migration mechanism; no protocol translation overhead.
  2. 2. Tunneling (e.g., 6to4, 6in4, Teredo):
    • Used when two IPv6 nodes or networks must communicate across an intervening IPv4-only transit network.
    • The ingress border router encapsulates the entire IPv6 datagram as payload inside an IPv4 datagram (Protocol 41). The packet traverses the IPv4 network as normal traffic.
    • The egress border router decapsulates the packet, strips the IPv4 header, and forwards the native IPv6 packet to the destination.
  3. 3. Header Translation (NAT-PT / SIIT / NAT64):
    • Required when an IPv6-only host must communicate directly with an IPv4-only host that cannot be upgraded.
    • The translator device strips the IPv6 header and synthesizes an equivalent IPv4 header (mapping 128-bit addresses to 32-bit addresses and adjusting total length, TTL/Hop Limit, and checksums).
    • Limitation: Information loss can occur because IPv6 lacks certain IPv4 header fields, and applications with embedded IP addresses (like FTP) require Application Layer Gateways (ALGs).
